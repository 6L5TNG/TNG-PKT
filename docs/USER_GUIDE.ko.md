## 1. 소개

TNG PKT는 아마추어무선 문자 교신 프로그램입니다. SSB 무전기와 컴퓨터 오디오 인터페이스를 통해 모뎀 소리를 보내고, 받은 소리를 문자로 복원합니다. TNG44, TNG5, TNG1은 속도와 오류 보호의 균형이 서로 다른 세 가지 모드입니다.

메시지는 오디오 연결로 전달됩니다. 선택적으로 사용하는 CAT는 컴퓨터에서 무전기를 제어하는 기능으로, 다이얼 주파수를 읽거나 바꿉니다. PTT는 무전기를 수신에서 송신으로 전환하는 제어입니다. 이 연결들은 역할이 다르므로, CAT가 연결되었다고 해서 송신 오디오까지 무전기에 들어가는 것은 아닙니다.

## 2. 처음 실행하기

Windows 배포판을 설치하고 시작 메뉴에서 **TNG PKT**를 실행합니다. 설치판에는 별도의 Python 설치가 필요하지 않습니다. 설치 방법과 이전 Build 1005에서 옮겨오는 방법은 [설치 문서](INSTALL.md)를 참고하십시오.

저장된 설정 파일이 없으면 메인 화면보다 먼저 **초기 설정** 창이 열립니다. **다음**, **이전**으로 이동합니다. 왼쪽 단계 이름을 클릭해서 단계를 건너뛰는 방식은 아닙니다.

1. **언어** — 한국어 또는 영어를 고릅니다. 첫 초기 설정에서는 선택한 언어가 바로 적용되며, 메인 화면도 그 언어로 열립니다.
2. **호출부호** — 자신의 호출부호를 입력합니다. 대문자로 저장되고 매크로의 `{MYCALL}`에 사용됩니다. 이 값을 입력해도 직접 작성한 모든 메시지에 호출부호가 자동으로 붙지는 않습니다.
3. **오디오** — **오디오 API**, **입력 장치**, **출력 장치**를 고릅니다. 입력은 무전기의 수신 소리가 PC로 들어오는 장치이고, 출력은 PC의 송신 소리가 무전기로 나가는 장치입니다. **입력 레벨**이 움직이는지 확인합니다. **시험음**은 선택한 출력으로 짧은 소리를 재생하며 CAT/DTR/RTS PTT 명령은 보내지 않습니다. 무전기가 VOX를 사용한다면 이 소리로 송신 상태가 될 수 있습니다.
4. **무전기** — **Rig**, **Serial Port**, **Baud Rate**, **PTT Method**와 시리얼 PTT용 **PTT Port**를 장비에 맞춥니다. **Test CAT**에서 `CAT OK`와 주파수·모드가 보이면 연결 확인에 도움이 됩니다. **Test PTT**는 CAT/DTR/RTS를 잠시 켰다가 자동으로 해제하며, VOX에서는 오디오가 송신을 켠다는 안내를 표시합니다. **건너뛰기**로 넘기고 나중에 전체 Radio 설정에서 연결할 수도 있습니다.
5. **진단** — **진단 실행**을 눌러 수신 처리 능력과 선택한 오디오 장치를 확인합니다. 약 30초를 예상하되 PC에 따라 달라질 수 있습니다. **건너뛰기**로 넘긴 뒤 나중에 실행해도 됩니다.
6. **완료** — **시작**을 눌러 설정을 저장하고 TNG PKT를 엽니다. 첫 초기 설정을 끝내기 전에 창을 닫으면 완료되지 않으며, 다음 실행 때 다시 나타납니다.

오디오만 연결해서 운용한다면 무전기 단계를 건너뛰거나 **Rig: None**, **VOX**를 사용합니다. 다이얼과 측파대는 무전기에서 직접 맞춥니다. 문자 교신에 CAT 연결이 필수인 것은 아닙니다. 나중에 **설정 → 일반 → 초기 설정 다시 하기**로 설정을 다시 진행하거나 **진단 다시 하기**로 점검할 수 있습니다. 메인 화면이 열린 뒤 바꾼 언어는 TNG PKT를 재시작하면 메인 화면에 적용됩니다.

## 3. 메인 화면 둘러보기

처음의 **운용** 레이아웃은 왼쪽에 스펙트럼과 워터폴, 오른쪽에 VFO·수신·송신을 배치합니다. 패널은 움직일 수 있으므로 배치가 다르면 제목을 보고 찾으십시오. 먼저 이 화면으로 교신을 익히면 됩니다. 모든 분석 그래프를 이해해야 교신할 수 있는 것은 아닙니다.

| 영역 | 무엇을 보여주나 | 어떻게 사용하나 |
|---|---|---|
| 상단 도구 막대 | 선택한 레이아웃과 모뎀 모드 | **운용**, **분석**, **전체**를 고르고 **TNG44**, **TNG5**, **TNG1**을 선택합니다. **패널 보기**에서 숨겨진 패널을 엽니다. |
| **VFO** | 첫 줄은 무전기 다이얼·밴드, 둘째 줄은 오디오 **중심**·계산된 **RF**·**PTT** | 무전기 주파수를 읽고, CAT 연결 시 다이얼을 바꾸거나 수신 신호에 맞게 중심을 조절합니다. |
| **FFT 스펙트럼** | 현재 각 오디오 주파수의 에너지 | 수신 곡선과 잡음, 생성된 송신 곡선을 비교합니다. 필요하면 dBFS 표시 범위를 조절합니다. |
| **워터폴** | 시간에 따른 오디오 주파수와 동기·구간 표시 | 신호를 찾고 실시간 화면에서 그 중심을 클릭해 중심 주파수를 맞춥니다. |
| **수신** | 읽을 수 있는 수신 문자와 현재 수신 상태 | 확정된 문자를 읽고 구간 진행을 확인하며, 복사하거나 현재 수신을 중지합니다. |
| **송신** | 여러 줄 메시지 입력과 진행률·남은 시간 | 내용을 입력하고 **송신**을 누릅니다. 송신 중에는 **중지**를 사용합니다. |
| **매크로** | 호출부호를 넣는 단축 문구, 별도의 한 줄 입력칸, 출력 음량 | **상대 호출부호**를 입력하고 매크로를 넣거나 이 패널에서 송신합니다. 송신 패널과는 별개의 입력칸입니다. |
| **수신 로그** | 수신 결과와 송신 사건을 모은 표 | 수신 행을 선택해 패킷을 살펴보고, WAV를 열거나 실시간 수신을 켜고 CSV로 내보냅니다. |
| **미터**, **채널 품질 / 통계** | 입력 레벨과 추정값, 패킷·세션 측정값 | 오디오 문제를 확인하거나 수신 결과를 비교할 때 패널 보기에서 엽니다. |
| 분석 패널 | 선택한 패킷 또는 실시간 수신기의 상세 자료 | 수신 로그의 행을 고른 뒤 분석 레이아웃이나 개별 패널을 사용합니다. |
| 아래 상태줄 | 준비 상태, 동작·오류, 모드 정보, 오디오 상태, 시계 | 문제가 생기면 여기의 오류부터 읽습니다. 잘린 정보는 마우스를 올려 전체 내용을 확인합니다. |

상단 **로그 폴더**는 현재 로그 위치를 엽니다. **설정**은 운용 구성을 바꾸고, **About**은 버전과 모델 정보를 보여줍니다. **Help**는 현재 `Coming soon` 안내만 표시합니다. 실제 사용 안내는 이 설명서와 패널의 **?**를 이용하십시오.

패널 제목에 마우스를 올리면 **?** 도움말, **⧉** 분리/다시 붙이기, **✕** 숨기기 조작이 나타납니다. 패킷 분석 패널은 새 오디오가 들어와도 이전 결과를 유지할 수 있습니다. 마지막 갱신 이후 경과 표시를 보면 현재 수신과 이전 결과를 구분하는 데 도움이 됩니다.

## 4. 모드 선택하기

양쪽 모두 **같은 모드**를 사용해야 합니다. 상단 선택은 실시간 수신과 송신에 함께 적용되며, 이 버전은 세 모드를 동시에 수신하지 않습니다. 모드를 바꾸면 진행 중인 수신 상태가 초기화되고, 송신 중에는 모드 변경이 잠깁니다.

| 모드 | 언제 고르나 | 운용할 때 달라지는 점 |
|---|---|---|
| **TNG44** | 비교적 양호한 채널에서 일반 문자 교신을 할 때, 세 모드 중 빠른 운용이 필요할 때 | 한글을 포함한 UTF-8 문자를 지원합니다. 양쪽이 안정적으로 받을 수 있다면 먼저 사용해 볼 모드입니다. |
| **TNG5** | 약한 신호나 페이딩으로 더 강한 오류 보호가 필요할 때 | 문자 속도를 낮추고 보호를 늘립니다. 문자가 확정될 때까지 더 기다립니다. |
| **TNG1** | 매우 어려운 조건에서 복원 가능성을 우선할 때 | 가장 느리며 약 14.7초 블록 단위로 수신하고 반복 합치기를 지원합니다. 처음에는 짧은 메시지를 사용하십시오. |

FEC는 전방 오류정정입니다. 추가로 전송한 정보를 이용해 수신기가 오류를 고치는 방식입니다. 복원 기회를 늘리지만, 심한 간섭이나 빠진 오디오까지 항상 해결하지는 못합니다. 모드를 바꿀 때는 상대국과 먼저 합의하십시오. TNG PKT가 자동으로 더 강한 모드를 선택하지는 않습니다.

TNG5와 TNG1은 대문자·숫자·공백·줄바꿈·일부 문장부호로 구성된 공통 57문자 집합을 사용합니다. 소문자는 대문자로, 탭은 공백으로 바뀝니다. 한글 등 지원하지 않는 문자가 있으면 **문자표 밖 글자** 경고가 나옵니다. 내용을 고치거나, 정확히 같은 내용을 다시 송신하면 해당 문자를 빼고 보냅니다. 자유로운 UTF-8 문자 교신이 필요하다면 TNG44를 사용하십시오. 모드 이름의 숫자는 현재 측정된 문자 속도가 아닙니다. 상세 수치는 [프로토콜 문서](PROTOCOL.ko.md)에 있습니다.

## 5. 워터폴과 스펙트럼 이해하기

### 화면 읽기

워터폴은 수신기에서 들어오는 소리의 이력을 보여줍니다. **가로축은 0–3000 Hz의 오디오 주파수**이며 무전기 다이얼의 MHz가 아닙니다. **세로축은 시간**입니다. 실시간 화면은 맨 위가 최신 소리이고 오래된 소리는 아래로 내려갑니다. WAV 파일 화면은 맨 위가 파일의 시작이며 아래로 갈수록 뒤의 시간입니다.

밝은 색은 표시 범위에 비해 에너지가 더 많다는 뜻입니다. 잡음은 넓게 퍼져 보이고, 계속되는 신호는 해당 오디오 주파수에 흔적을 남깁니다. 흔적이 밝거나 뚜렷하다는 사실만으로 TNG PKT 신호나 복조 성공을 판단할 수는 없습니다.

FFT 스펙트럼은 시간 이력 대신 현재의 오디오 주파수별 에너지를 보여줍니다. 수신 곡선은 입력, 송신 곡선은 생성된 송신 오디오이며 **피크 홀드**는 최근의 봉우리를 유지합니다. 세로축 **dBFS**는 디지털 오디오의 최대 크기를 기준으로 한 데시벨입니다. 안테나에서 측정한 RF 출력이 아닙니다. **하한**, **상한**, **자동**은 레벨 표시 범위를 바꿉니다. 자동은 누를 때 한 번 맞춥니다.

### 오디오 중심 맞추기

VFO의 **중심**은 모뎀의 오디오 중심 주파수이며 기본값은 **1500 Hz**입니다. 영어 화면의 이름은 **Offset**입니다. 송신 소리를 어디에 놓을지, 실시간 수신기가 선택한 모드를 어디에서 찾을지 정합니다. 중심 실선과 대역 안내선으로 신호 위치를 비교할 수 있습니다. 안내선은 화면 기준이며, 그 사이의 모든 신호를 복조한다는 보장은 아닙니다.

수신 신호를 맞출 때는 다음 순서로 진행합니다.

1. 상대국의 모드를 고르고 수신 오디오가 들어오는지 확인합니다.
2. 신호가 차지한 오디오 대역의 가운데를 찾습니다.
3. **실시간 워터폴**에서 그 주파수를 왼쪽 클릭하거나 **중심**에 값을 입력합니다. 값은 10 Hz 단위로 맞춰집니다.
4. 새 송신 또는 블록을 기다린 뒤 CRC를 통과한 문자가 나오는지 확인합니다.

클릭 튜닝은 실시간 워터폴에서만 동작합니다. 무전기 다이얼이 아닌 오디오 중심을 바꿉니다. 진행 중인 수신도 초기화되므로 끝까지 읽고 싶은 메시지 중에는 클릭하지 않는 편이 좋습니다. 송신 중에는 중심이 잠깁니다. 선택 범위는 모드마다 제한되어 명목 신호 대역이 300–2700 Hz 안에 들어가도록 합니다.

### 수신 탐색 범위 이해하기

0–3000 Hz 화면 어디에 신호가 보인다고 해서 수신기가 그 위치까지 찾는 것은 아닙니다. 실시간 수신기는 선택한 중심 부근을 탐색합니다. 명목 주파수 오차 탐색 범위는 **TNG44/TNG5가 ±100 Hz**, **TNG1이 ±60 Hz**입니다. 이는 신호의 점유 대역폭이 아니라 중심에서 어긋난 정도를 찾는 범위입니다. 세부 보정·추적도 수행하지만 탐색 한계에 맞춰 운용하지는 마십시오.

중심에서 많이 벗어난 신호는 다음 송신 전에 가운데를 클릭해 맞춥니다. 무전기 오디오 통과 대역의 가장자리에 있다면 전체 신호가 통과하도록 무전기 다이얼·필터를 조절한 뒤 중심을 다시 맞춥니다. 그래프를 확대해도 무전기 필터가 잘라낸 소리는 되살아나지 않습니다.

**실시간 워터폴**은 움직이는 화면을, 수신 로그의 **실시간 수신**은 복조를 별도로 제어합니다. **구간 표시**는 겹쳐 그린 표시를 켜고 끕니다. **흐름**은 화면에 담기는 시간 이력을, **컬러맵**은 색상을 바꿉니다. 이 보기 설정은 모드를 바꾸거나 오류 보호를 강화하지 않습니다.

## 6. VFO와 무전기 제어

VFO는 가변 주파수 발진기를 뜻합니다. 여기서는 무전기 다이얼을 제어하고 무전기 주파수와 모뎀 오디오의 관계를 보여주는 패널 이름입니다.

**첫 줄**에는 큰 다이얼 표시, 밴드 단축 선택, 연결 상태가 있습니다. CAT 연결 시 다이얼은 무전기를 따라갑니다. 숫자 자리 위에서 휠을 돌리면 그 자리 값을 바꾸고, 클릭하면 직접 입력합니다. 예를 들어 `14.078`은 MHz, `14078000`은 Hz입니다. Enter로 적용하고 Escape로 취소합니다. 밴드를 고르면 저장된 단축 다이얼 주파수를 무전기로 보냅니다.

**둘째 줄**에는 오디오 Hz 단위의 **중심**, 전파상 신호 중심을 계산한 **RF**, 누르는 동안 동작하는 **PTT**가 있습니다. USB 다이얼 14.078000 MHz에 중심 1500 Hz라면 RF 중심은 14.079500 MHz입니다. LSB/data-L에서는 다이얼에서 중심을 뺍니다. 실제 측파대와 필터는 무전기에서 확인하십시오. 메인 화면에 별도의 무전기 모드 선택기는 없습니다.

CAT가 없으면 **연결되지 않음**으로 표시되고 다이얼/RF는 빈 자리 표시가 되며 밴드·다이얼 조작은 꺼집니다. 중심은 계속 사용할 수 있습니다. CAT 없이 운용할 때는 무전기의 다이얼 화면을 보십시오. 앱은 확인되지 않은 수동 주파수를 측정된 RF처럼 표시하지 않으며 로그의 RF도 비워 둡니다.

Hamlib는 기종별 무전기 제어를 제공하고, **rigctld**는 그 제어를 담당하는 백그라운드 서비스입니다. TNG PKT가 로컬 rigctld를 시작하거나 이미 실행 중인 서비스에 연결할 수 있습니다. Windows 배포판에 Hamlib는 포함되어 있지 않습니다. CAT를 사용한다면 별도로 설치하십시오. 연결 안내는 [설치 문서](INSTALL.md#licenses-and-radio-connection-security)에 있습니다.

## 7. 메시지 수신하기

1. 상대국과 모드·측파대·신호 위치를 맞춥니다. 수신 로그의 **실시간 수신**을 켭니다. 패널이 없으면 **패널 보기 → 수신 로그**로 엽니다.
2. 입력 장치에 무전기 소리가 들어오는지 확인합니다. 움직이는 워터폴과 입력 레벨은 입력의 증거이지만 복조 성공의 증거는 아닙니다.
3. 신호가 들어오는 동안 중심을 유지합니다. 수신기는 시간과 주파수 위치를 찾기 위한 알려진 신호 모양, 즉 동기를 찾습니다. TNG1은 블록 안의 동기를 사용하므로 확정까지 더 기다릴 수 있습니다.
4. 워터폴 표시를 봅니다. **자홍색 점선 표지·상자는 첫 CRC 통과 전의 후보 표시**입니다. 정상 수신된 문자가 아닙니다. 끝내 확정되지 않은 후보는 사라질 수 있습니다.
5. CRC 검사를 기다립니다. CRC는 받은 구간이나 블록에 오류가 있는지 확인하는 검사입니다. 첫 부분이 통과하면 수신 패널에 메시지를 열고 후보 표시를 정상 상태 색으로 바꿉니다. **CRC를 통과한 구간은 초록 실선, 실패한 구간은 빨강, 대기 부분은 점선**입니다. 시작·끝 동기 상자는 별도의 안내이며 전체 문자 구간의 통과를 뜻하지 않습니다.
6. 수신 문자와 구간 수를 함께 읽습니다. 검사된 부분이 생길 때마다 글자가 이어집니다. 끝의 **▍**는 다음 부분을 기다림, **□**는 실패하거나 빠진 부분입니다. 읽을 수 있는 문장에 빈 부분이 있으면 부분 복원입니다.
7. 끝나면 최종 상태와 수신 로그 결과를 확인합니다. **부분 복원** 또는 실패라면 전체를 받았다고 가정하지 말고 빠진 내용을 다시 요청하십시오.

첫 CRC는 해당 부분을 확인한 것이며 전체 송신을 확인한 것은 아닙니다. 뒤에 성공 구간과 실패 구간이 섞일 수 있으므로 완료되거나 신호가 소실될 때까지 기다립니다. 수신 패널의 **중지**는 받은 부분까지 복조하도록 요청하고 다시 수신 대기로 돌아갑니다. 실시간 복조 자체를 끄는 실시간 수신 체크 해제와 다릅니다.

TNG1에서 송신국의 **다시 보내기**는 직전 메시지를 처음부터 반복합니다. 수신기는 대응되는 반복 블록을 합쳐 나중에 빠진 부분을 복원할 수도 있습니다. 자동 재요청·응답 체계는 아니므로 상대 운용자와 반복을 조율하고, 여전히 CRC 결과를 확인하십시오.

## 8. 메시지 송신하기

송신하기 전에 주파수가 비어 있는지, 사용할 무전기·오디오 경로가 맞는지 확인합니다.

1. 합의한 **TNG44**, **TNG5**, **TNG1**을 고릅니다.
2. 무전기 다이얼·측파대·오디오 중심을 확인합니다. CAT 연결 시 VFO의 다이얼/RF를 무전기와 비교하고, CAT가 없으면 무전기에서 직접 확인합니다.
3. **설정 → Radio → PTT Method**와 **설정 → 오디오 → 출력 장치**를 확인합니다. 인터페이스·무전기에 맞게 **출력 음량**을 정합니다. 이는 오디오 크기이며 와트 설정이 아닙니다. 무전기의 출력·ALC를 보고 입력을 과하게 밀어 넣지 않도록 합니다.
4. 여러 줄 **송신** 입력칸에 메시지를 작성하고 필요한 호출부호도 넣습니다. **송신**을 누릅니다. 지원하지 않는 문자 경고가 나오면 다시 누르기 전에 내용을 읽습니다.
5. 송신 중 입력칸은 편집할 수 없게 됩니다. 진행률·**남은 시간**과 구간 강조를 봅니다. 흐린 글자는 송신 완료, 빨간 강조는 송신 중인 부분입니다. 이는 내 PC의 진행 상태이며 상대국 수신 확인이 아닙니다.
6. 완료되면 앱은 오디오를 멈추고 CAT/DTR/RTS에 PTT 해제를 요청한 뒤 송신 조작을 되돌립니다. VOX는 소리가 끝난 뒤 무전기의 VOX 지연에 따라 해제됩니다. 일반 실시간 수신은 송신 중 잠시 멈추고 이후 다시 시작합니다.
7. 상대국의 응답을 기다려 실제 수신 여부를 확인합니다.

**중지**를 한 번 누르면 진행 중인 구간·블록에 필요한 부분을 마친 뒤 정상적으로 끝내도록 예약합니다. 송신 패널의 버튼은 **즉시 중단**으로 바뀝니다. 다시 누르면 바로 멈춥니다. 이미 끝에 가까우면 **끝 부분이라 중지 안 됨** 안내와 함께 남은 끝부분을 마칠 수 있습니다. 즉시 중단하면 상대국에 불완전한 메시지가 남을 수 있습니다.

TNG1의 **다시 보내기**는 TNG1 송신 후 활성화됩니다. 입력칸을 수정했더라도 마지막으로 송신한 정규화된 내용을 다시 보냅니다. 새 내용을 보내려면 송신을 사용합니다.

매크로 패널에서도 송신할 수 있습니다. 별도의 **보낼 내용** 한 줄 입력칸에 작성한 뒤 **송신**을 누르거나 Enter를 누릅니다. **즉시 송신**이 켜져 있으면 매크로를 클릭하자마자 보냅니다. 먼저 내용을 확인하려면 이 체크를 꺼 두십시오.

**설정 → Radio → TNG Options → Max TX Time**은 연속 송신·수동 PTT 시간을 제한합니다. 기본은 300초이며 초과하면 오디오를 멈추고 PTT 해제를 요청합니다. 긴 TNG1 메시지는 이 한도에 닿을 수 있습니다. 장비에 적합한 제한을 정하고 필요하면 메시지를 짧게 나눕니다.

## 9. PTT와 무전기 제어 설정

동작 중이 아닐 때 **설정 → Radio**에서 구성합니다. CAT는 무전기 제어이고 **PTT Method**는 송신을 켜는 방법입니다. DTR/RTS PTT는 주파수 CAT 없이도 사용할 수 있습니다.

### VOX

무전기나 인터페이스가 소리로 송신을 켠다면 **VOX**를 사용합니다. TNG PKT는 오디오를 보내며 제어선을 켜지 않습니다. 무전기·인터페이스의 VOX를 켜고 조절한 뒤 올바른 출력 장치를 선택하고 메시지 앞부분이 잘리지 않는지 확인합니다. **VOX Lead Tone**은 모뎀 소리 앞에 톤을 추가해 전환 시간을 줄 수 있습니다. Test PTT만으로는 VOX 오디오 경로를 시험하거나 톤으로 무전기를 켜지 않습니다.

### CAT

무전기의 Hamlib 백엔드가 PTT를 지원한다면 **CAT**를 사용합니다. 실제 **Rig**, CAT 포트·시리얼 값을 고르고 먼저 **Test CAT** 성공을 확인한 뒤 PTT를 시험합니다. **Transmit Audio Source**의 **Rear/Data**, **Front/Mic**는 지원되는 CAT PTT에서 입력 커넥터를 선택합니다. 실제 오디오가 들어가는 쪽을 고르십시오. 주파수 제어 성공과 PTT·오디오 입력 선택 지원은 각각 확인해야 합니다.

### DTR

인터페이스가 시리얼 DTR 제어선으로 PTT를 켠다면 **DTR**를 사용합니다. PTT **Port**를 고르거나, 같은 포트를 공유하도록 설계된 인터페이스라면 CAT 포트를 사용합니다. 이 신호를 무전기 PTT로 바꾸는 케이블·인터페이스가 필요합니다. DTR 선택 자체가 오디오 연결을 만드는 것은 아닙니다. 다른 프로그램이 포트를 점유하지 않도록 합니다.

### RTS

RTS 선으로 연결된 인터페이스는 **RTS**를 사용합니다. DTR와 비슷하게 설정하지만 실제 하드웨어에 연결된 선을 골라야 합니다. CAT의 **Force Control Lines**는 시리얼 포트 구성이며 PTT Method 선택을 대신하지 않습니다. 인터페이스가 권장하는 값을 유지하십시오.

### Hamlib 연결과 결과 확인

**TNG Options**의 **Start rigctld with TNG**는 Rig·시리얼 설정으로 로컬 서비스를 시작합니다. 자동으로 찾지 못하면 **rigctld Path**를 지정합니다. **Connect to running rigctld**는 이미 실행된 서비스의 **rigctld Address**를 사용합니다. 기본은 `127.0.0.1:4532`입니다. 기존 서비스의 실제 기종·연결 구성에 맞추십시오. 클라이언트 값을 바꿔도 그 서비스의 시리얼 연결을 다시 구성하지는 않습니다. 설치 문서에 안내된 신뢰할 수 있는 연결을 사용합니다.

**Poll Interval**은 CAT 값을 읽는 간격입니다. **Mode: None**은 무전기 모드 선택을 운용자에게 맡기고, **USB**, **Data/Pkt**는 해당 무전기 모드를 요청합니다. 처음에는 **Split Operation: None**이 이해하기 쉽습니다. **Rig**는 무전기 분할 송신을, **Fake It**은 송신 중 다이얼을 일시적으로 옮겨 생성 오디오를 1500 Hz 부근에 유지하는 방식을 사용합니다. 지원 여부는 무전기·백엔드에 따라 다르므로 장비에서 확인한 뒤 사용하십시오.

**Tx delay**는 CAT/DTR/RTS로 PTT를 켠 뒤 모뎀 소리까지 무음을 둡니다. VFO의 **PTT**는 누르는 동안 제어만 켜고 모뎀 소리는 보내지 않습니다. 설정의 **Test PTT**는 약 3초 뒤 자동 해제하고 첫 초기 설정의 시험은 약 2초입니다. 이 시험은 실제 송신기를 켤 수 있습니다. 앱은 송신 완료·중단·오류·종료에도 해제를 요청하고, CAT PTT 송신 중 CAT가 끊기면 송신을 중단합니다. 새 인터페이스를 시험할 때는 무전기에서도 해제 여부를 확인하십시오.

## 10. 오디오 설정

입력과 출력은 PC 관점에서 생각하면 쉽습니다.

| 선택 | 필요한 경로 | 흔한 잘못된 선택 |
|---|---|---|
| **입력 장치** | 무전기 수신 소리 → 컴퓨터 | 노트북 마이크: 방 안 소리에 워터폴이 반응하지만 무전기 신호는 들어오지 않습니다. |
| **출력 장치** | 컴퓨터 모뎀 소리 → 무전기 송신 입력 | PC 스피커·헤드폰: 주변에서는 소리가 나지만 무전기에 변조가 들어가지 않습니다. |

USB 오디오가 있는 무전기는 USB 사운드 장치로 표시될 수 있습니다. 외부 인터페이스도 일반적인 이름을 사용할 수 있습니다. Windows 기본 장치는 헤드셋이나 내장 사운드일 수 있으므로 이름만 믿지 말고 무전기와 연결된 경로를 따라 양방향을 확인하십시오.

먼저 **오디오 API**를 고른 뒤 그 API에 표시되는 입력·출력 장치를 고릅니다. Windows 설치판은 MME, DirectSound, WDM/KS, WASAPI를 지원하며 ASIO는 제공하지 않습니다. 한 API에서 장치를 열지 못하면 다른 사용 가능한 API를 시도하고 입력·출력을 다시 고릅니다.

**설정 → 오디오**에서 바꾼 뒤 **적용**은 저장·반영하고 창을 유지하며, **확인**은 적용 후 닫습니다. **취소**는 아직 적용하지 않은 일반 설정 편집을 버립니다. 송신 또는 메시지 수신 중에는 장치 변경이 잠기므로 동작을 완료·중지한 뒤 바꿉니다. 패널 보기에서 연 별도의 오디오 패널은 장치를 직접 바꾸고 기억합니다.

정상적인 수신 경로라면 **입력 레벨**이 무전기 소리에 반응하고 실시간 워터폴에도 수신기의 신호·잡음 변화가 보입니다. 거의 무음이면 연결을, 최대 레벨에 닿으면 클리핑을 의심합니다. 수신 크기는 무전기·인터페이스 또는 Windows에서 조절합니다. 앱의 출력 음량은 수신 이득을 바꾸지 않습니다. 송신은 초기 설정의 시험음이나 짧은 메시지와 의도한 PTT 방식으로 무전기의 변조·출력 표시를 확인합니다. 진단에서 장치를 열었다는 결과만으로 케이블이나 무전기 메뉴 경로까지 확인되는 것은 아닙니다.

장치는 이름과 API로 저장됩니다. 저장된 USB 장치가 없으면 다른 장치나 기본 장치가 선택될 수 있습니다. 장비를 뽑았거나 Windows 오디오 구성을 바꿨다면 다시 확인하십시오. 아래 상태줄과 툴팁에서 실제 선택된 장치 이름을 읽을 수 있습니다.

## 11. 레이아웃과 작업 화면

레이아웃은 패널을 배치한 모양이며 다른 무전기·모뎀 설정이 아닙니다. 패널을 숨겨도 관련 기능이 꺼지는 것은 아닙니다. 예를 들어 수신 패널을 숨기는 것은 실시간 수신을 끄는 동작이 아닙니다.

- **운용**은 큰 워터폴과 읽기 쉬운 수신·송신, VFO를 제공합니다. 교신이나 작은 화면에 적합합니다.
- **분석**은 패킷 그래프·수신 로그·품질 측정을 중심으로 합니다. 일부 송신 도구는 다른 패널 뒤의 탭으로 배치됩니다. 탭 이름을 눌러 앞으로 가져옵니다.
- **전체**는 여러 열에 운용·분석 도구를 함께 놓습니다. 큰 화면에서 쓰기 좋고 일부 영역은 탭을 공유합니다. 패킷 해부·대역 확대 워터폴·TNG1 격자는 필요할 때 별도로 엽니다.

패널의 **제목줄**을 끌어 옮기고, 패널 사이 경계를 끌어 크기를 바꿉니다. 제목 위에 마우스를 올리고 **⧉**를 누르면 별도 창으로 분리하거나 다시 붙입니다. **✕**로 숨긴 패널은 **패널 보기**에서 되살립니다. 아주 작아지면 패널 안에 스크롤 막대가 나타날 수 있습니다. 화면을 조절하는 것이므로 메시지를 삭제하거나 모뎀을 바꾸는 동작이 아닙니다.

**분석 창 분리**는 성상도·아이·특징·LLR·동기·추이 묶음을 별도 분석 창으로 옮깁니다. 두 번째 모니터에서 유용합니다. 다시 누르거나 분석 창을 닫으면 본창으로 돌아옵니다. 나머지 패널은 개별적으로 분리할 수 있습니다.

일반 화면으로 돌아가려면 분리한 분석 묶음을 되돌리고 **운용**을 누릅니다. 프리셋을 적용해도 떠 있는 패킷 해부·확대·격자 창은 남을 수 있으므로 필요하면 따로 닫습니다. 별도의 레이아웃 초기화 버튼은 없습니다.

정상 종료 시 창 크기·위치, 프리셋, 분석 창 분리 정보를 `layout.ini`에 저장합니다. **이 빌드는 시작할 때 저장된 본창 도킹 상태 전체를 복원하는 대신 선택한 프리셋을 다시 적용합니다.** 임의로 바꾼 모든 패널 위치·탭·숨김 상태가 그대로 돌아온다고 기대하지 마십시오. 오디오와 운용자 설정은 별도로 저장됩니다.

일반 교신은 운용에서 시작하고 기록을 함께 보고 싶으면 수신 로그를 엽니다. 어려운 수신을 살펴보려면 분석을 선택하고 해당 수신 행의 패킷 해부를 엽니다. 화면 밖으로 나간 창이나 이상한 배치를 도구 막대로 되돌릴 수 없다면 문제 해결의 되돌릴 수 있는 레이아웃 파일 초기화를 참고하십시오.

## 12. QSO와 운용 영역

QSO는 무선 교신입니다. TNG PKT의 운용 영역은 문자 교환 화면과 사건 로그이며 ADIF 교신 입력 양식이나 자동 교신 확인 기능을 제공하지 않습니다.

**수신**은 현지 날짜·시각·모드 구분선 아래에 메시지를 쌓습니다. **따라가기**는 최신 문자로 돌아갑니다. 위로 스크롤하면 따라가기를 멈추고 맨 아래로 내리면 다시 따라갑니다. **가− / 가 / 가+**는 글자를 작게·기본 크기로·크게 바꿉니다. **복사**는 선택한 글자를 복사하고, 선택이 없으면 현재 메시지의 복원 문자·빈 부분 표현을 복사합니다. **지우기**는 화면만 비우며 저장된 세션 로그를 지우지 않습니다.

**송신**에는 작성할 내용을 넣습니다. 그 진행률은 내 송신 상태이고 수신에는 상대국이 실제로 보낸 내용이 나타납니다. 보낸 모든 내용이 수신 대화창에 자동으로 쌓이지는 않으므로 송신 이력은 수신 로그에서 확인합니다.

**매크로**의 **상대 호출부호**에는 상대국을 직접 입력합니다. `{MYCALL}`은 설정 → 일반의 내 호출부호, `{DXCALL}`은 상대 호출부호, `{SNR}`은 유지 중인 SNR 값을 사용합니다. 매크로 클릭은 매크로 패널의 한 줄 입력칸을 채우며 여러 줄 송신 입력칸을 채우지 않습니다. **즉시 송신**이 켜져 있으면 바로 보냅니다. 매크로를 오른쪽 클릭해 편집·삭제하고, 추가 조작 또는 설정 → 매크로에서 새 항목을 만듭니다. 임의의 수신 문장에서 상대 호출부호를 알아서 채워주는 기능으로 생각하지 말고 답신 전에 확인하십시오.

**수신 로그**에는 UTC, 결과, SNR, Δf, 구간, 드리프트, 재동기, FEC, RF, 내용/사유가 있습니다. 구간은 자료가 있을 때 통과/전체를, FEC는 정정한 비트 수를 나타냅니다. RF는 CAT 정보를 사용할 수 있을 때 기록합니다. 송신·중지 사건도 나오지만 송신 행이 상대국의 수신 증거는 아닙니다. 분석 자료가 있는 수신 행을 선택하면 패킷 패널이 바뀌고 패킷 해부가 열립니다. 내용·사유 위에 마우스를 올려 자세히 읽습니다.

## 13. 분석 도구

분석은 일반 교신에 필수가 아닙니다. “시작을 찾았나?”, “어느 부분이 CRC에 실패했나?”, “TNG1 반복 블록이 도움이 되었나?”를 알아볼 때 사용합니다. **분석** 또는 **패널 보기**를 연 뒤 관련 **수신 로그** 행을 고릅니다. 분석 자료가 없는 행은 표시할 내용이 없을 수 있습니다. 비어 있거나 알 수 없는 값은 오류가 0이라는 뜻이 아닙니다.

### 패킷 타임라인과 채널 품질 / 통계

**패킷 타임라인**은 위에 프레임, 아래에 구간 CRC를 놓습니다. 초록은 통과, 노랑은 FEC 정정, 빨강은 실패·확인 가능한 오류입니다. 프레임·구간에 마우스를 올려 상세를 보고 클릭해 대응되는 부분을 강조합니다. 프레임의 정오 판단은 해당 구간 비트 중 실제로 검사할 수 있는 부분에 한정됩니다.

**채널 품질 / 통계**는 선택한 패킷의 hard 판정 BER, FEC 정정/확인 비트, SNR, 등화 후 EVM, 시작 동기 상관, 잔여 드리프트와 세션 수치를 보여줍니다. BER은 복원한 기준으로 확인 가능한 hard 판정 비트 오류이며, FEC는 남은 문자 오류가 아니라 고친 비트 수입니다. SNR은 잡음에 대한 신호 크기의 추정값입니다. EVM은 채널 왜곡을 보상하는 등화 후 재구성한 신호와의 차이를 나타냅니다. 상관은 알려진 동기 패턴과의 일치 정도입니다. 처음에는 **CRC 결과와 구간 수**부터 보십시오. 이 추정값 하나만으로 문자가 맞다고 증명할 수는 없습니다.

**미터**는 입력 레벨·SNR 추정·주파수 오차·복원 여유를 보여줍니다. 주파수 오차는 선택한 오디오 중심과 확정된 동기를 기준으로 합니다. 복원 여유는 SNR 추정에서 고정 기준 −6.5 dB를 뺀 표시입니다. 모든 모드·채널에 적용되는 보편적인 복조 한계는 아닙니다. **추이 (최근 패킷)**는 최대 60개 패킷의 측정값을 UTC에 따라 그립니다. 한 점보다 여러 수신의 변화를 비교하십시오.

### IQ 성상도·아이 다이어그램·NN 특징 / 위상 궤적

**IQ 성상도**는 수신 기호의 신호 성분을 그립니다. **등화**는 재구성한 채널 보정을 사용하고 **원본**은 주파수·위상만 보정합니다. 같은 패킷의 두 보기를 비교하면 왜곡을 살펴볼 수 있지만, 점이 모여 보인다는 사실 자체가 CRC 통과는 아닙니다.

**아이 다이어그램**은 두 심볼 길이의 궤적을 겹쳐 시간에 따른 파형 변화를 보여줍니다. 등화/원본 선택은 성상도와 공유합니다. 일반 교신에서는 닫아 두어도 됩니다. 숙련자는 같은 패킷의 보정 전후 궤적을 비교할 수 있습니다.

**NN 특징 / 위상 궤적**은 신경망 수신기가 비트를 결정하기 전 특징을 2차원에 투영한 보기와 선택 프레임의 I/Q 궤적입니다. 투영 그래프는 시각화이며 수신 문자나 직접적인 SNR 값이 아닙니다. 패킷 타임라인에서 프레임을 골라 궤적을 살펴봅니다. 색·정확도 해석에는 확인 가능한 기준이 필요하며 알 수 없는 부분에는 그 기준이 없습니다.

### LLR 분포와 코스타스 동기 맵

LLR은 비트 판정의 확신도를 나타내는 부드러운 판단값입니다. **LLR 분포**는 그 판단값이 어떻게 퍼져 있는지 보여줍니다. 분홍·파랑은 기준 비트를 알고 있는 경우의 색이고 회색은 기준을 모르는 경우입니다. 절댓값이 크면 강한 판단일 수 있지만 강하게 틀린 판단도 가능합니다. CRC와 확인 가능한 비트 자료를 함께 보십시오.

**코스타스 동기 맵**은 시간·주파수 오차에 따른 동기 점수를 보여줍니다. 초록 윤곽은 검출 문턱, 원은 최대점, 더하기는 검출 위치입니다. **실시간**, **스냅샷**으로 현재 탐색과 저장된 검출 보기를 구분합니다. 컬러맵·**부드럽게**는 표시를 바꿉니다. 동기 봉우리는 후보 위치이지 유효한 본문 보장이 아닙니다. TNG5 패킷은 자료가 있으면 전용 동기 자료를 사용합니다.

### 패킷 해부: TNG44와 TNG5

**패킷 해부**는 사용자가 여는 패킷 dissect 기능입니다. 수신 로그 행을 선택하면 자료가 있을 때 대응 창이 열립니다. `dissect.py`나 `dissect5.py`를 따로 실행할 필요가 없습니다.

여러 층의 보기는 오디오에서 주파수 보정 I/Q, 프레임·구간, 부드러운 판단값, 순서를 복원하고 정정한 비트, CRC, 바이트·문자로 이어집니다. **층을 클릭**하면 다른 층의 대응 위치를 강조하고 항목 트리에 상세를 표시합니다. 빨간 삼각형은 오류정정이 바꾼 위치입니다. 긴 패킷은 **이전 / 다음**, 페이지당 구간 수, 위의 개요 막대로 이동합니다. 이 화면은 가로 이동·확대를 지원하며 **처음으로**는 첫 페이지·보기로 돌아갑니다.

TNG5 층에는 중간 동기와 반복 합치기도 나타납니다. TNG5 결과에 대체 요약 자료만 있으면 구간 표로 표시하며 CRC16·글자·프레임·평균 절대 LLR·정정 수·바이트·내용을 보여줍니다. 처음에는 실패한 CRC 구간과 대응하는 문자 빈 부분부터 찾으십시오. 고급 사용자는 그 구간을 비트 층으로 거슬러 살펴볼 수 있습니다. 정정 표시는 복조기가 값을 바꿨다는 뜻이며 반드시 실패라는 뜻은 아닙니다.

### TNG1 분석

TNG1은 같은 분석 위치에 다른 패널을 사용하며 TNG1 패킷 선택으로도 보기가 바뀔 수 있습니다. 신경망 수신 모델을 사용하지 않으므로 NN 관련 그래프를 TNG1 복조의 같은 척도로 해석하지 마십시오.

| 도구 | 무엇을 살펴보나 | 먼저 볼 부분 |
|---|---|---|
| **16음 격자 · TNG1** | 시간에 따른 톤 칸, 위의 수신·아래의 송신, 동기와 FEC가 바꾼 칸 | 흰 테두리는 CRC 통과 기호입니다. 블록 경계를 클릭해 해부를 봅니다. |
| **기호 확신도 · TNG1** | 가장 강한 톤 칸과 두 번째 칸의 비율 | 모호한 칸은 불확실성을 설명하지만 그 비율이 CRC 통과는 아닙니다. |
| **동기 누적 지도 · TNG1** | 블록 위상·주파수 오차에 따른 누적 동기 근거 | 후보 위치와 누적 블록 수를 봅니다. 봉우리가 있어도 CRC 전에는 후보입니다. |
| **동기 12음 · TNG1** | 각 동기 톤의 점수 | 한 톤이 높으면 성공이라고 보기보다 12개 기여가 어떻게 다른지 봅니다. |
| **패킷 해부 · TNG1** | 블록 선택, 기호 판정·정정, 복원 비트·CRC·문자 | 블록의 CRC 결과와 복원된 문자를 봅니다. |
| **송신 해부 · TNG1** | 문자 부호화, 블록 비트와 송신 톤 기호 구성 | 현재 어느 블록을 보내는지 봅니다. |

격자에 보이는 블록에 대응되는 복조 자료가 없으면 **해부 자료 없음**이 나올 수 있습니다. 실시간 화면에 나타났다는 이유만으로 CRC를 통과한 패킷 자료가 만들어지지는 않습니다.

### 송신 모니터와 송신 해부

**송신 모니터**는 로컬 송신 단계·현재 구간·경과/남은 시간·실효 속도를 보여줍니다. 데이터 기준 실효 속도는 데이터 시작 이후 완료 구간의 글자 수를, 전체 기준은 시작 준비 시간까지 포함합니다. 따라서 짧은 메시지 속도는 긴 메시지의 데이터 속도와 다를 수 있습니다. 프레임 이동과 **송신 따라가기**로 현재 위치를 봅니다.

**송신 해부**는 바이트·정보 비트·부호 비트·송신 순서를 보여줍니다. 흐린 부분은 송신 완료, 빨간 위치선은 로컬 진행입니다. TNG1은 위에서 설명한 블록 전용 보기를 사용합니다. 이 화면은 내 송신 신호를 설명하며 상대국 수신 품질을 측정하지 않습니다.

## 14. 확대와 보기 조작

**패널 보기 → 대역 확대 워터폴**을 열면 현재 중심 부근을 자세히 볼 수 있습니다. 위는 스펙트럼, 아래는 워터폴이며 중심·대역·톤 안내선과 자료가 있을 때 검출 주파수 오차선을 표시합니다.

- **범위**는 중심을 기준으로 **±150**, **±300**, **±500 Hz**를 선택합니다.
- **분해능**은 **시간 우선 (4Hz)**, **균형 (2Hz)**, **주파수 우선 (1Hz)**입니다. 주파수를 더 세밀히 보려면 더 긴 시간 창을 사용합니다. 짧은 변화는 시간 우선, 가까운 톤 분리는 주파수 우선으로 살펴봅니다.
- **흐름**은 표시 이력을, **구간 표시**는 겹쳐 그린 표시를 바꿉니다.
- **하한 / 상한 / 자동**은 레벨 표시 범위를 바꾸며 자동은 누를 때 최근 입력에 한 번 맞춥니다.

일반 확대 보기로 돌아가려면 **±300 Hz**, **균형 (2Hz)**를 선택하거나 창을 닫고 전체 워터폴을 봅니다. 확대 설정은 기억됩니다. 그래프를 바꾸는 기능이므로 수신 탐색 범위나 무전기 다이얼은 바뀌지 않습니다. 튜닝은 전체 실시간 워터폴이나 VFO 중심에서 합니다.

수신 글자는 **가− / 가 / 가+**와 수신 패널에 포커스가 있을 때 **Ctrl+−**, **Ctrl++ / Ctrl+=**, **Ctrl+0**으로 조절합니다. 가독성만 바뀝니다. 패킷 해부의 가로 이동·확대와 처음으로 조작도 별개이며 오디오 튜닝과 혼동하지 마십시오.

## 15. 설정

설정은 **일반, Radio, 오디오, 모드, 수신/표시, 매크로**로 구성됩니다. 일반 편집은 적용·확인으로 반영합니다. 취소가 이미 적용한 값을 되돌리지는 않습니다. 특히 **Test CAT/Test PTT는 시험 전에 Radio 값을 적용**하며, 초기 설정·진단 다시 하기는 일반 설정 편집과 별개로 결과를 저장할 수 있습니다.

### 일반

**내 호출부호**는 자신의 매크로 호출부호입니다. **시계**는 상태줄에서 UTC·현지·둘 다를 고릅니다. 수신 로그는 UTC, 수신 구분선은 현지 시각을 유지합니다. **언어**는 재시작 후 바뀝니다. **초기 설정 다시 하기**는 장비를 바꾼 뒤 유용하고 **진단 다시 하기**는 현재 오디오 선택을 점검합니다. **로그 폴더 → 찾아보기**는 이후 로그 세션의 위치를 고르며 재시작 후 적용됩니다. 기존 로그는 자동으로 이동하지 않습니다.

### Radio

Rig·시리얼은 CAT, PTT Method·Port는 송신 제어에 사용합니다. 일반 사용자는 Data Bits·Stop Bits·Handshake를 장비 기본값에 두고 시작할 수 있습니다. 잘못된 기종·포트·속도는 연결을 막고 잘못된 제어선은 PTT를 막을 수 있으므로 교신 전 시험합니다. TNG Options에는 rigctld 연결·경로, Max TX Time, VOX Lead Tone이 있습니다. **Bands**에서 단축값을 추가·삭제·편집하거나 **Defaults**로 되돌립니다. **Dial (MHz)**는 개인 단축 주파수이며 공식 TNG PKT 호출 주파수 목록이 아닙니다. 송신·PTT 시험·PTT 누름 중에는 Radio 조작이 잠깁니다.

### 오디오

오디오 API·입력·출력·출력 음량을 설정합니다. 실시간 입력 레벨로 수신 경로를 확인합니다. API를 바꾸면 장치 목록이 달라지므로 양쪽 선택을 다시 확인합니다. 메시지 수신·송신 중에는 장치 선택이 잠기니 먼저 동작을 끝냅니다.

### 모드

**시작 시 모드**에서 **마지막 모드** 또는 **항상 TNG44**를 고릅니다. 이는 시작할 때의 선택이며 현재 교신 모드는 상단에서 고릅니다. 자동 모드 변경이나 모든 모드 수신을 켜는 설정이 아닙니다.

### 수신/표시

**수신 글자 크기**는 읽는 글자를, **컬러맵**은 워터폴 색을 바꿉니다. 수신 감도나 CRC 동작은 바뀌지 않습니다.

### 매크로

이름·내용을 편집하고 **추가**로 새 항목을 만들거나 선택 항목을 **삭제**합니다. `{MYCALL}`, `{DXCALL}`, `{SNR}`을 사용할 수 있습니다. 실제 치환된 내용과 모드의 지원 문자를 송신 전에 확인하십시오. 호출부호가 비어 있으면 답신 문구도 불완전하므로 먼저 채웁니다.

## 16. 진단

초기 설정 또는 **설정 → 일반**에서 진단을 실행합니다. 선택한 입력·출력 장치를 열고 TNG44·TNG5·TNG1 수신 처리 시간을 측정합니다. 결과에는 CPU 한 코어의 처리 여유, 오디오 샘플레이트·버퍼 누락·측정 가능한 클럭 오차가 포함됩니다. 처리 여유는 오디오 길이와 처리 시간을 비교한 값이며 클수록 실시간 처리를 따라갈 시간이 많습니다.

실제 한국어 결과는 적합 / 주의 / 부적합이며 영어 UI는 Pass / Warning / Fail입니다.

| 결과 | 의미 | 무엇을 하나 |
|---|---|---|
| **적합** (Pass) | 측정 항목이 적합 기준을 충족했습니다. | 설정을 마친 뒤 실제 무전기 오디오와 짧은 교신으로 확인합니다. |
| **주의** (Warning) | CPU 여유 감소, 버퍼 누락, 오디오 샘플레이트·클럭 우려 등이 있습니다. | 사유를 읽고 PC 부하를 줄이거나 장치·API를 확인한 뒤 다시 실행합니다. |
| **부적합** (Fail) | 처리 여유가 기준보다 낮거나, 클럭 오차가 크거나, 장치·점검 오류가 있습니다. | 표시된 문제를 해결한 뒤 실시간 수신에 사용합니다. |

CPU는 한 코어 처리 여유가 3배 이상이면 적합, 1.5배 이상이면 주의, 그보다 낮으면 부적합입니다. 오디오는 버퍼 누락이나 권장 48 kHz와 다른 샘플레이트에 주의를 표시할 수 있습니다. 사유를 구분하십시오. **장치를 열지 못함**은 연결·설정 문제이며 전파 상태 측정이 아닙니다. **결과 없음**이나 진단 실패도 적합 판정이 아닙니다.

결과는 설정과 함께 저장되므로 장치·PC를 바꾸면 이전 결과가 현재 상태를 나타내지 않을 수 있습니다. 진단은 RF 경로·상대국 수신·안테나·간섭·전체 장비 호환성을 측정하지 않습니다. 적합 판정이 실제 전파에서 프로토콜 성능을 보장하는 것은 아닙니다.

## 17. 로그와 저장 데이터

Windows 사용자 데이터의 기본 위치는 **`%APPDATA%\TNG PKT`**입니다. 파일 탐색기 주소창에 붙여 넣거나, 현재 로그 위치는 상단 로그 폴더로 엽니다.

| 항목 | 용도 | 사용 방법 |
|---|---|---|
| `settings.json` | 호출부호·장치·무전기·매크로·최근 진단 | 평소에는 설정 창에서 바꾸고 문제 해결·초기화 전 백업합니다. |
| `layout.ini` | 창 위치·크기·프리셋·분석 창 배치 정보 | 앱이 관리합니다. 시작 시 복원 제한은 레이아웃 설명을 참고합니다. |
| `logs/` | 기본 세션·진단/타이밍 기록 위치 | 문제 보고에 필요한 파일을 보관합니다. 사용자 로그 폴더를 지정하면 위치가 달라집니다. |
| `session_YYYYmmdd_HHMMSSZ.jsonl` | 실행 세션의 RX/TX 사건을 한 줄씩 기록 | 운용 이력이며 `Z`는 UTC입니다. 전체 오디오 녹음은 아닙니다. |
| `latency_YYYYMMDD.csv` | 자동으로 쓰는 타이밍 정보 | 주로 문제 해결용이며 일반 교신에서 해석할 필요는 없습니다. |

수신 로그의 **CSV 내보내기**는 **현재 실행 세션**의 RX/TX 기록을 지정한 위치에 저장합니다. UTC·방향·결과·사용 가능한 신호/오류 측정·모드·다이얼/RF·문자가 포함됩니다. 이전의 모든 로그 파일을 자동으로 모으지는 않습니다. 스프레드시트에서 읽기 쉽도록 BOM이 있는 UTF-8을 사용합니다.

**WAV 열기**는 오디오 파일의 워터폴을 표시하고 지원 모드를 자동으로 판별해 복조를 시도합니다. 선택 모드만 받는 실시간 수신과 다른 동작입니다. 워터폴은 파일 보기로 바뀌므로 이후 현재 입력으로 돌아가려면 **실시간 워터폴**을 다시 켭니다. 이전 파일 형식의 호환 범위는 프로토콜 문서를 참고하십시오.

매크로의 **WAV 저장**은 **그 패널의 한 줄 보낼 내용으로 TNG44 송신 WAV를 생성**합니다. 수신 오디오를 녹음하거나 여러 줄 송신 입력칸을 사용하지 않으며, TNG5/TNG1을 선택했어도 해당 모드로 내보내지 않습니다. 현재 무전기·PTT·음량 구성 전체가 아니라 TNG44 엔진의 표준 파형을 사용합니다. 이 버전에는 사용자가 켜는 연속 수신 WAV 녹음 기능이 없습니다.

설정 → 일반에서 로그 폴더를 바꾸면 다음 실행부터 적용되고 기존 파일은 원래 위치에 남습니다. 쓰기 가능한 폴더를 고르십시오. 평소에 데이터 파일을 직접 편집할 필요는 없으며 제거·업데이트 시 사용자 데이터 폴더는 보존됩니다.

## 18. 일반적인 교신 순서

USB 무전기·인터페이스와 TNG44를 사용하는 예입니다. 운용에 맞는 SSB 주파수를 상대국과 합의하십시오. 앱의 밴드 단축값은 주파수 권장 목록이 아닙니다.

1. 무전기 USB·시리얼·오디오 인터페이스를 연결하고 무전기를 켭니다. 의도한 USB/data-USB 오디오 경로를 선택합니다.
2. 설정 → 오디오에서 해당 인터페이스 입력·출력을 고릅니다. 입력 레벨과 실시간 워터폴로 무전기 소리를 확인합니다.
3. 설정 → Radio에서 필요하면 CAT를 구성하고 의도한 PTT 방식을 시험합니다. CAT가 없으면 Rig None/VOX를 사용합니다.
4. **운용**, **TNG44**를 고릅니다. 상대 운용자와 모드·RF 신호 위치를 맞춥니다.
5. 무전기 다이얼을 맞춥니다. 중심은 **1500 Hz**에서 시작하고 CAT가 있으면 VFO/RF를 확인합니다.
6. 실시간 수신을 켜고 전체 워터폴을 봅니다. 상대 신호가 어긋나면 다음 메시지 전에 가운데를 클릭합니다.
7. 자홍 점선 후보 표시 뒤 CRC를 통과한 문자가 나올 때까지 기다립니다. 전체 메시지와 □·부분 복원을 확인합니다.
8. 송신에 짧은 답신을 씁니다. 예를 들어 `6L5TNG DE YOURCALL TNX UR MSG K`의 호출부호를 실제 양쪽 호출부호로 바꿉니다.
9. 송신을 누르고 남은 시간과 무전기의 송신 표시를 봅니다. 소리가 끝나면 수신으로 돌아가는지 확인합니다.
10. 상대국 응답을 읽습니다. 반복 실패하면 오디오·모드·튜닝부터 확인하고, 맞다면 TNG5/TNG1 변경에 합의한 뒤 양쪽이 바꿉니다. 해당 모드에서는 지원되는 대문자 문구를 사용합니다.
11. 편리하다면 상대 호출부호를 입력하고 내용을 검토한 매크로를 사용합니다. 익숙해질 때까지 즉시 송신은 꺼 둡니다.
12. 교신 후 수신 로그를 보고 필요하면 CSV를 내보냅니다. 실패 수신은 행을 선택해 패킷 해부의 CRC·구간 자료를 확인합니다.

## 19. 문제 해결

오디오 경로와 모드부터 확인하고 더 상세한 분석으로 진행하십시오. 초기화 전 설정과 관련 로그를 보관합니다.

### 1. 프로그램은 열리지만 수신하지 못함

수신 로그의 **실시간 수신**을 켜고 모델 로딩이 끝났는지 확인합니다. 선택 모드·입력 장치·중심을 확인합니다. 앱이 실행 중이거나 화면이 움직인다는 사실만으로 복조가 켜져 있는 것은 아닙니다.

### 2. 워터폴이 비어 있거나 멈춤

**실시간 워터폴**을 확인합니다. WAV 열기는 파일 보기로 바꿉니다. 입력 레벨·물리적 수신 오디오 경로·오디오 API·입력 장치를 봅니다. 화면 표시를 끈 것과 입력이 무음인 것은 다릅니다. 상태줄의 장치 열기 오류도 읽습니다.

### 3. 신호는 보이지만 복조되지 않음

상대 모드와 호환되는 릴리스·프로토콜을 사용합니다. 신호 중심을 탐색 범위 안에 맞추고 전체 대역이 무전기 필터를 통과하도록 합니다. 측파대·클리핑·간섭을 확인합니다. 메시지 중간에 모드·중심을 바꿨다면 새 시작·블록을 기다립니다.

### 4. 자홍 점선이나 대기 표시만 나옴

후보는 찾았지만 본문 CRC는 아직 통과하지 않았습니다. 특히 TNG1/TNG5는 충분히 기다리고 신호 위치·오디오 레벨을 확인합니다. 끝내 확정되지 않으면 문자 없이 후보가 사라질 수 있습니다. 완료된 메시지로 해석하지 마십시오.

### 5. □가 있거나 ▍가 남고 부분 복원으로 끝남

일부가 실패했거나 아직 수신 중입니다. 끝까지 기다린 뒤 최종 구간 수를 봅니다. 빠진 부분을 다시 요청합니다. TNG1은 송신국에 같은 메시지의 다시 보내기를 요청하면 대응 블록을 합칠 수 있습니다. 신호 소실·이른 송신 중단도 불완전한 문자를 남길 수 있습니다.

### 6. 상대가 내 신호를 받지 못함

모드·주파수를 합의하고 무전기가 실제로 송신하며 변조된 RF를 내는지 확인합니다. 출력 장치·무전기 입력 메뉴·PTT Method·출력 음량을 봅니다. 진행률은 내 재생 상태입니다. 지원 문자로 짧게 보내고 상대국의 중심 위치도 확인합니다.

### 7. 송신 오디오가 없거나 PC 스피커로 나옴

선택한 API에서 실제 무전기·인터페이스 **출력 장치**를 고릅니다. **출력 장치가 없음**, **재생 실패** 안내를 읽습니다. 필요하면 초기 설정의 시험음으로 경로를 확인합니다. 장치 목록이나 적합 판정만으로 출력 케이블이 무전기에 연결되었다고 확인할 수는 없습니다.

### 8. PTT가 켜지지 않거나 너무 늦게 해제됨

VOX는 무전기·인터페이스에서 켜고 오디오를 확인합니다. Test PTT만으로는 톤을 보내지 않습니다. CAT는 CAT OK와 백엔드 PTT·오디오 입력 지원을 확인합니다. DTR/RTS는 포트·배선을 확인하고 다른 포트 사용 프로그램을 닫습니다. 앞부분이 잘리면 Tx delay·VOX Lead Tone을 검토합니다. VOX 해제 지연은 무전기에서 조절합니다.

### 9. CAT 연결 실패

Rig 기종·COM 포트·Baud Rate·시리얼 값을 확인합니다. 로컬 rigctld를 사용할 때는 Hamlib를 설치하고 필요하면 경로를 지정합니다. 기존 서비스는 호스트·TCP 포트와 실행 상태를 확인합니다. 다른 프로그램이 CAT 포트를 사용할 수도 있습니다. Test CAT는 편집한 Radio 값을 적용한 뒤 시험합니다.

### 10. 무전기 주파수 표시가 다르거나 비어 있음

CAT가 없을 때 연결되지 않음과 다이얼/RF 빈 표시는 정상입니다. 연결 시 먼저 **다이얼**을 비교하고 **RF 중심**에는 오디오 중심이 반영됨을 기억합니다. USB는 더하고 LSB는 뺍니다. 측파대·Poll Interval을 확인합니다. Split/Fake It은 송신 다이얼을 일시 이동할 수 있으므로 모르면 Split None에서 시작합니다.

### 11. 모드 변경·워터폴 클릭 후 수신이 끊김

이 버전에서는 수신 상태를 초기화합니다. 메시지를 먼저 끝내거나 변경 후 새 송신·블록을 기다립니다. 송신 중 모드·중심이 잠기는 것은 의도된 동작입니다. 송신을 끝내거나 중지한 뒤 바꿉니다.

### 12. TNG5/TNG1에서 문자를 보내지 못함

문자표 밖 글자 안내를 읽고 지원하지 않는 문자를 지우거나 UTF-8·한글은 TNG44로 보냅니다. 같은 내용으로 다시 누르면 해당 글자를 빼므로 그 전에 검토합니다. 지원 문자가 하나도 남지 않으면 송신할 수 없습니다.

### 13. USB 인터페이스가 바뀌거나 다른 장치가 선택됨

다시 연결하고 설정 → 오디오에서 API부터 고른 뒤 입력·출력을 다시 선택합니다. 저장된 장치 이름이 없으면 기본 장치로 바뀔 수 있습니다. 조작이 잠겼다면 현재 수신·송신을 끝낸 뒤 바꿉니다.

### 14. 모델·자원 오류

상태줄과 **About → Copy Version Info**를 확인합니다. 자원이 빠졌거나 손상되면 해당 공식 패키지를 다시 설치합니다. 소스 실행은 `models/stage3.pt`, `models/stage3_strong.pt`, `assets/`, `style.qss`의 문서화된 구조를 유지합니다. 불일치 안내를 없애려고 무관한 모델로 교체하면 호환되지 않을 수 있습니다. TNG1 자체는 신경망 모델을 사용하지 않지만 앱은 다른 수신 자원도 초기화합니다.

### 15. 진단 주의·부적합 또는 진단 미완료

어느 모드·장치에서 어떤 사유인지 읽습니다. CPU는 무거운 백그라운드 작업을 닫고 다시 측정합니다. 오디오는 장치·API·사용 가능 여부와 버퍼 누락·샘플레이트·클럭 오차를 확인합니다. 구성을 바꾸면 재진단하십시오. 저장된 이전 결과는 현재 시험이 아닙니다.

### 16. 배치가 이상하거나 패널이 사라짐

패널 보기에서 다시 열고 분석 창 분리를 되돌린 뒤 운용을 선택합니다. 떠 있는 특수 패널은 필요하면 따로 닫습니다. 창이 화면 밖에 있다면 앱을 닫고 `%APPDATA%\TNG PKT\layout.ini`를 백업·이름 변경한 뒤 재시작하여 기본 배치를 만듭니다. 운용 설정·로그는 지우지 않고 보기만 초기화합니다.

### 17. 설정이 꼬이거나 초기 설정이 나타나지 않음

일반적인 복구는 설정 → 일반 → 초기 설정 다시 하기를 사용합니다. 전체 초기화가 필요하면 TNG PKT를 닫고 사용자 폴더의 `settings.json`을 백업·이름 변경한 뒤 다시 시작해 초기 설정을 마칩니다. 호출부호·오디오·무전기·매크로를 다시 입력해야 하므로 로그·레이아웃은 따로 보관합니다. 잘못된 JSON은 자동으로 `settings.broken-...json`에 백업하고 기본값을 사용합니다. 실행 중인 설정 파일을 직접 편집하지 마십시오.

### 18. 메시지가 끝나기 전에 송신이 멈춤

상태줄에서 Max TX Time 초과·PTT 실패·CAT 끊김을 확인합니다. 메시지를 줄이거나 장비에 적합한 Max TX Time을 정합니다. 예약 중지는 남겨 둔 부분만 마치고, 즉시 중단은 구간을 자를 수 있습니다. 재시도 전에 무전기가 수신으로 돌아왔는지 확인합니다.

## 20. 아마추어무선 운용

TNG PKT는 공개 아마추어무선 문자 교신용입니다. 비밀키 메시지 암호화 기능은 없습니다. 프로토콜과 전파상 부호화는 공개되어 있으며 오류정정·화이트닝은 신호 처리 기능이지 비밀 통신 기능이 아닙니다. 메시지에 적절한 식별을 포함하고 자신의 운용 자격 범위에서 사용하십시오. 상세 부호화는 [프로토콜 문서](PROTOCOL.ko.md)에 있습니다.
