# TNG PKT 프로토콜 설계와 동작

[English](PROTOCOL.md) | [한국어](PROTOCOL.ko.md)

이 문서는 2026-09-29 기준 **TNG PKT 0.11.2 Beta / Build 1009** 공개 소스를 설명합니다. 초기 설계나 이전 실험 설정이 아니라 현재 활성 송수신 경로를 다룹니다.

## 개요

TNG PKT는 아마추어무선의 공개 교신을 전제로 합니다. 현재 무선 송수신 경로에는 메시지 암호화, 비밀키 통신, 메시지 은닉 기능이 없습니다. 여기서 설명하는 문자 부호화, CRC, 순방향 오류 정정(FEC), 인터리빙(interleaving), 동기, 고정된 공개 화이트닝(whitening)은 통신을 위한 처리이며 비밀성을 위한 처리가 아닙니다. 공개 모델 가중치는 TNG44/TNG5 파형 정의의 일부이며 비밀키가 아닙니다.

TNG PKT는 SSB 송수신기의 오디오 경로를 통해 대화형 문자 교신을 합니다. 세 모드는 프레이밍(framing), 오류 보호, 신호 포착 방식이 서로 다른 독립적인 통신 모드입니다. 하나의 공통 전송 형식에 대한 속도 프리셋이 아닙니다. 무선국은 송수신 전에 모드를 선택합니다.

TNG44는 비교적 양호한 HF 채널에서 처리량을 우선합니다. TNG5는 약한 신호와 페이딩에 대비해 중복 정보와 인터리빙에 더 많은 송신 시간을 사용합니다. TNG1은 긴 블록과 매우 낮은 문자 전송률을 감수하고, 반복된 내용의 수신 관측을 결합하는 방법을 포함해 복원을 우선합니다. 이는 설계 목표이며, 측정된 채널 문턱값이나 성능 보장이 아닙니다. 이름에 포함된 숫자는 현재의 초당 문자 수를 뜻하지 않습니다.

전체 처리 순서는 아래 공통 경로에서, 정확한 전송 구조는 각 모드 절에서 확인할 수 있습니다. 문자표와 파형 정의가 공개되어 있으므로, 다른 구현에서도 이 문서와 연결된 소스, 제공되는 모델 가중치로 부호화 방식을 재구성할 수 있습니다.

## 범위와 표기 규칙

| 모드 | 설계상 역할 | 프로토콜 버전 | Wire revision | 주요 구현 |
|---|---|---|---|---|
| TNG44 | Standard | 0.1.0 | 1 | [link7](../tngpkt/link7.py), [modem5](../tngpkt/modem5.py), [realtime_rx](../tngpkt/realtime_rx.py) |
| TNG5 | Robust | 0.4.0 | 4 | [tng5](../tngpkt/tng5.py), [tng5_app](../tngpkt/tng5_app.py) |
| TNG1 | Robust+ | 0.1.1 | 2 | [tng1](../tngpkt/tng1.py), [tng1_app](../tngpkt/tng1_app.py) |

버전은 [registry.py](../tngpkt/registry.py)를 기준으로 합니다. 일부 소스 주석과 모듈 내부 버전 문자열은 이전 구현을 가리키며, 현재 활성 정의를 대체하지 않습니다.

- 바이트 필드는 NumPy의 기본 `unpackbits`/`packbits` 순서에 따라 최상위 비트부터 전송합니다. 두 바이트 길이·개수 필드와 바이트 단위 CRC 값은 빅엔디언 순서입니다.
- 아래 배열 위치는 영부터 시작합니다. 부호 비트는 왼쪽에서 오른쪽으로 읽습니다.
- **세그먼트(segment)**는 TNG44/TNG5의 CRC 단위입니다. 학습형 모뎀의 **프레임(frame)**은 부호화된 96비트를 전달하며 길이는 192 ms입니다. TNG1의 **블록(block)**은 별도의 구조로, 92개 톤 심볼이 14.72초 동안 이어집니다.
- 기본 오디오 중심 주파수는 1500 Hz입니다. TNG44/TNG5는 초당 2000개의 복소 기저대역 샘플을, TNG1은 초당 1000개의 샘플을 사용합니다. 리샘플링 후 `real(baseband * exp(j*2*pi*center*t))`를 취해 오디오를 만듭니다.
- 중심 주파수 선택, 출력 이득, 오디오 리샘플링, 선택적 VOX 선행 톤·PTT 지연은 정보 부호화 외부에서 동작합니다. [modem](../tngpkt/modem.py), [freqshift](../tngpkt/freqshift.py), [neuromod_app](../tngpkt/neuromod_app.py)의 UI 송신 경로를 참고하십시오.
- 실시간 수신은 선택한 모드만 사용합니다. 각 모드는 독립적인 통신 모드이며, 모든 모드를 자동으로 수신하는 프로토콜이 아닙니다.

[framing.py](../tngpkt/framing.py) 상단의 이전 96비트 헤더·페이로드 형식은 현재 활성 TNG44/TNG5 세그먼트 형식이 **아닙니다**. 현재 경로는 해당 모듈의 CRC 함수를 재사용하며, 프레이밍은 아래에 별도로 정의합니다.

## 공통 송신 경로

공통적인 흐름은 다음과 같습니다.

```text
문자 -> 바이트 또는 문자 부호화 -> 세그먼트 분할 / 블록 프레이밍
     -> CRC -> FEC -> 모드별 순서 재배열과 파형 처리
     -> 동기를 포함한 파형 -> SSB 송신기로 오디오 출력
```

이 흐름은 기능을 목적별로 묶어 나타낸 것이며, 모든 모드에 동일한 처리 순서를 강제하지 않습니다. 특히 **TNG5 화이트닝은 CRC 계산 후, FEC 부호화 전에 수행**하며, TNG1은 변조 전에 톤 시퀀스에 동기 심볼을 삽입합니다.

| 단계 | 현재 활성 구현의 동작 |
|---|---|
| 문자 부호화 | TNG44는 NUL을 제거하고 UTF-8 바이트로 부호화합니다. TNG5/TNG1은 제한된 문자 집합에 맞게 정규화한 뒤, 공개 Huffman 문자 부호를 완전한 문자 단위로 채웁니다. |
| 프레이밍 | TNG44는 페이로드 바이트 수를 앞에 붙이고 패딩된 바이트열을 세그먼트로 나눕니다. TNG5는 고정 크기 세그먼트를 사용하며 첫 세그먼트에 전체 세그먼트 수를 넣습니다. TNG1은 독립적인 문자 블록을 채우며 EOT가 포함될 때까지 계속합니다. |
| CRC | 각 세그먼트나 블록에 오류 검출용 공개 체크섬을 붙입니다. CRC는 오류를 정정하거나 송신자를 인증하지 않습니다. |
| FEC | TNG44는 세그먼트 스트림을 연속적으로 컨볼루션 부호화합니다. TNG5는 각 세그먼트를 부호화하고 부호어를 반복합니다. TNG1은 각 블록을 테일바이팅(tail-biting) 부호화하여 톤 레이블로 만듭니다. FEC는 중복 정보를 추가하여 수신기가 불확실한 관측으로 정보를 복원할 수 있게 합니다. |
| 모드별 순서 재배열 | 모든 모드는 부호 비트나 심볼을 인터리빙합니다. TNG5만 FEC 전에 세그먼트 데이터를 화이트닝합니다. 인터리빙은 인접한 채널 오류를 복호기 입력에 분산시키며 비밀 매핑을 추가하지 않습니다. |
| 동기와 변조 | TNG44/TNG5는 부호 비트와 가드를 공개 파형 모델로 매핑한 뒤, 데이터 스트림 앞뒤 또는 내부에 모드별 선행·동기 신호를 배치합니다. TNG1은 각 블록 전체에 알려진 동기 톤을 삽입한 뒤, 전체 톤 시퀀스를 처프가 있는 16-GFSK로 변조합니다. |
| 오디오 출력 | 기저대역 파형을 리샘플링하고 선택한 오디오 중심 주파수로 옮겨 무전기의 SSB 오디오 입력으로 보냅니다. 출력 이득과 선택적 PTT/VOX 타이밍은 프로그램·무전기 인터페이스의 기능입니다. |

인터리빙과 FEC는 수신의 서로 다른 측면을 보호합니다. 페이딩은 연속된 전송 위치를 손상시킬 수 있으며, 인터리빙은 오류 정정 전에 그 관측을 재분배합니다. 어느 쪽도 손실된 세그먼트나 블록의 복원을 보장하지 않습니다.

## 공통 수신 경로

```text
수신 오디오 -> 복소 기저대역 -> 동기 / 타이밍 / 주파수 포착
            -> 연판정 복조 -> 디인터리빙
            -> 모드별 결합 -> FEC 복호
            -> 모드별 디화이트닝 -> CRC 검증
            -> 바이트 / 문자 복호 -> 복원된 문자
```

연판정 복조(soft demodulation)는 각 비트나 톤을 즉시 결정하지 않고 불확실성을 유지합니다. TNG44/TNG5는 부호 있는 비트 로그우도비(LLR)를 사용하며, TNG1은 가능한 톤 레이블별 메트릭을 사용합니다. 비터비(Viterbi) 복호는 이 관측을 이용해 컨볼루션 부호와 일치하는 정보 시퀀스를 선택합니다.

- **TNG44:** 시작·끝 동기를 검출하고 타이밍과 주파수를 추정한 뒤, 모델 LLR을 구하고 디인터리빙하여 연속 비터비 복호를 수행합니다. 세그먼트 CRC를 검증하고 가능한 경우 바이트 수 필드를 복원한 뒤, 유효한 바이트를 모아 UTF-8로 복호합니다.
- **TNG5:** 시작·끝 또는 중간 동기를 포착하고 데이터 창에서 중간 동기 샘플을 제외한 뒤, 모델 LLR을 구하고 디인터리빙합니다. 정렬된 네 부호어 사본을 합산하고 각 세그먼트를 비터비 복호한 다음, 화이트닝을 되돌리고 원본 데이터의 CRC를 검증하여 유효한 세그먼트를 Huffman 복호합니다. 화이트닝 대상은 전송된 부호 비트가 아니라 정보 바이트이므로, 디화이트닝(de-whitening)은 FEC 복호보다 먼저 수행할 수 없습니다.
- **TNG1:** 분산된 동기 톤으로 블록을 포착하고, 오디오에서 처프를 제거해 톤 에너지를 측정한 뒤, 심볼 순서를 복원하고 테일바이팅 비터비 복호를 수행합니다. Huffman 복호 전에 CRC와 수신기 확인 규칙을 검증합니다. 실패 후보는 아래 설명처럼 재시도하거나 다른 관측과 결합할 수 있습니다. TNG1에는 디화이트닝 단계가 없습니다.

CRC로 확인된 내용만 문자 표시 대상이 되며, 수신기에서 요구하는 경우 추가 포착·확인 검사도 거칩니다. 누락된 부분에는 대체 표시나 앞부분 누락 표시가 남을 수 있습니다. 뒤쪽 세그먼트나 블록을 복원했다고 앞의 문자까지 복원되는 것은 아닙니다.

## 등록된 기준 전송률

아래 값은 [registry.py](../tngpkt/registry.py)에 등록된 값이며 새로운 RF 측정 결과가 아닙니다. 데이터 구간 전송률은 긴 메시지의 증분 기준이며, TNG5에는 반복적으로 들어가는 중간 동기 오버헤드가 포함됩니다. 전체 송신 기준은 동기를 포함한 24자 메시지를 사용합니다. 짧은 메시지, UTF-8 바이트 길이, Huffman 부호 길이, 수신 실패에 따라 실효 처리량은 달라집니다.

| 모드 | 데이터 구간 문자/s | 정보 비트/s | 전체 송신 문자/s (24자 기준) | 정보 비트/s (같은 기준) | 등록된 −60 dB 점유대역폭 |
|---|---:|---:|---:|---:|---:|
| TNG44 | 29.5 | 236 | 11.2 | 89 | 470 Hz |
| TNG5 | 4.8 | 24.6 | 3.2 | 17.0 | 423 Hz |
| TNG1 | 0.90 | 4.35 | 0.82 | 4.08 | 356 Hz |

TNG44 문자 전송률은 ASCII 바이트를 기준으로 하며, 일반 유니코드 문자를 고정된 문자/s로 환산할 수는 없습니다. TNG5/TNG1 전송률은 공통 Huffman 부호화와 메시지 내용에 따라 달라집니다. 등록된 인터리버 범위는 각각 3.2 s, 9.6 s, 14.7 s입니다. TNG1의 값은 블록 내부 인터리버를 나타내며 블록 뒤에 추가되는 지연이 아닙니다.

## 공개 문자 매핑

### TNG44: UTF-8

송신기는 U+0000을 제거하고 나머지 문자열을 Python UTF-8로 부호화합니다. Huffman 문자표 없이 해당 바이트를 전달합니다. 부호화 함수를 직접 호출할 때 입력이 비어 있으면 공백 하나로 표현하며, UI는 빈 메시지를 거부합니다. ASCII는 문자당 한 바이트이며 한글 음절은 일반적으로 세 바이트입니다.

앞부분 길이 필드는 문자 수가 아니라 **바이트 수**입니다. 수신에 성공하면 페이로드 바이트를 모아 UTF-8로 복호합니다. 부분 수신에서는 인접한 유효 세그먼트를 이어 붙인 뒤 복호합니다. 누락 세그먼트 경계의 불완전한 UTF-8 시퀀스는 버리고, 실패한 세그먼트는 표시용 대체 기호로 나타냅니다. 대체 기호는 수신기 표시 규칙이며 전송된 문자가 아닙니다.

### TNG5/TNG1 공통 정규 Huffman 코드북(canonical Huffman codebook)

두 모드는 [charset1.py](../tngpkt/charset1.py)를 사용하며, 입력 문자 57자와 내부 EOT 종료 기호로 구성됩니다. 입력 정규화는 정확히 다음과 같습니다.

```python
t = text.upper().replace("\r\n", "\n").replace("\r", "\n").replace("\t", " ")
```

`CHARS`에 없는 문자는 정규화 시 보고하고 제거합니다. UI는 지원하지 않는 문자를 제외하고 송신하기 전에 경고합니다. 두 모드 모두 일반 UTF-8 문자를 전달하지 않습니다.

공개된 심볼 순서는 다음과 같습니다.

```python
CHARS = "ABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789 \n.,?'/-=()!:+\"@&;*#%"
SYMS = CHARS + "\x04"  # internal EOT
```

아래 표는 소스에서 추출한 현재 `charset1.CODE`의 정확한 내용입니다. EOT는 내부 제어 기호이며 추가 사용자 입력 문자가 아닙니다.

| 심볼 | 부호 비트 (왼쪽에서 오른쪽) |
|---|---|
| `A` | `0100` |
| `B` | `101100` |
| `C` | `01100` |
| `D` | `101101` |
| `E` | `0101` |
| `F` | `1110010` |
| `G` | `101110` |
| `H` | `01101` |
| `I` | `01110` |
| `J` | `11110010` |
| `K` | `101111` |
| `L` | `01111` |
| `M` | `110000` |
| `N` | `10000` |
| `O` | `10001` |
| `P` | `110001` |
| `Q` | `110010` |
| `R` | `10010` |

## TNG44: Standard

### 설계 목적과 절충

TNG44는 비교적 양호한 HF 채널에서 빠른 문자 교신을 목표로 하며, 세 모드 중 처리량을 우선합니다. 바이트 단위 UTF-8 전송은 Robust 모드의 문자표로 문자를 제한하지 않습니다. 페이로드 바이트 수를 통해 수신기는 표시 문자 수와 무관하게 메시지 범위를 정할 수 있습니다.

현재 경로는 세그먼트 CRC, 연속 K7 R1/2 컨볼루션 부호, 지연 인터리버, 명시적인 시작·끝 동기를 사용합니다. R1/4 부호와 네 개의 완전한 사본을 사용하는 TNG5보다 중복 정보에 쓰는 송신 시간이 적으며, TNG1의 긴 톤 심볼과 반복 내용 복원을 사용하지 않습니다. 그 결과 정보 비트당 중복 정보가 적고 같은 시간에 더 많은 문자를 전달하는 절충을 택합니다. 이것이 모든 조건에서의 성능 순위를 입증하지는 않습니다.

이 모드에서는 학습형 신호 처리 구성요소가 활성 경로에서 동작합니다. `StreamTransmitter`는 부호 비트 쌍과 프레임 내 위치를 I/Q 샘플로 매핑하며, `ContextReceiver`는 주변 문맥을 포함한 I/Q 창을 연판정 비트 값으로 변환합니다. 파형 매핑과 복조는 이 구성요소가 수행하고, 프레이밍·CRC·FEC는 명시적인 알고리즘이 처리합니다. [공개 모델 절](#tng44tng5-파형-매핑과-공개-모델)에 기술적 역할과 호환성 요구 사항을 정의합니다. 등록된 29.5 ASCII 문자/s는 긴 메시지의 증분 전송률이며, 이름의 “44”를 뜻하지 않습니다.

### 송신 정보 경로

```text
문자 -> NUL 제거 -> UTF-8 바이트
     -> 2바이트 페이로드 바이트 수 + 페이로드
     -> 용량 패딩 -> 세그먼트 + CRC16
     -> 연속 K7 R1/2 FEC + 마지막 테일
     -> 결정론적 지연 인터리버 -> 96비트 프레임
     -> 앞뒤 가드 -> 공개 파형 모델
     -> 톤 + 시작 동기 + 모뎀 데이터 + 끝 동기 -> 오디오
```

1. 페이로드 앞에 두 바이트 빅엔디언 길이를 붙입니다. 따라서 첫 세그먼트는 길이 필드 뒤에 최대 30바이트의 문자를 담으며, 이후의 완전한 세그먼트는 32바이트의 문자를 담습니다.
2. 패딩 전 세그먼트 스트림과 FEC 테일이 들어가는 최소 96비트 프레임 수를 선택합니다. 길이 필드가 붙은 바이트열을 `capacity(n_frames)`까지 NUL 바이트로 채웁니다. 이는 세그먼트 CRC와 FEC 테일을 포함해 해당 프레임에 들어가는 최대 바이트 수입니다.
3. 이 바이트열을 최대 32바이트 세그먼트로 나눕니다. 패딩과 첫 세그먼트의 길이 필드를 포함해 **각 세그먼트**에 CRC 두 바이트를 붙입니다.
4. 모든 세그먼트와 CRC 비트를 이어 붙이고, **메시지 끝에 한 번만 여섯 개의 영 테일 비트**를 추가한 뒤 세그먼트 경계를 넘어 연속적으로 컨볼루션 부호화합니다. 세그먼트는 독립적인 FEC 부호어가 아닙니다.
5. 부호 비트를 인터리빙합니다. 남은 부호 프레임 위치는 `default_rng(0xF111).integers(0, 2, count)`로 생성한 고정 공개 NumPy 시퀀스로 채웁니다. 이 채움은 부호화된 정보·CRC 바깥에 있습니다.
6. 데이터 프레임 앞뒤에 96비트 가드 프레임을 하나씩 추가합니다.

페이로드 길이가 `L`바이트일 때, 용량 패딩 전 계산은 다음과 같습니다.

```text
N = L + 2
S = ceil(N / 32)
coded_bits = 2 * (8 * (N + 2*S) + 6)
n_frames = ceil(coded_bits / 96)
```

`capacity`는 패딩 가능한 바이트 수에도 같은 부호 길이 규칙을 적용합니다. 가드 프레임은 `coded_bits`나 `n_frames`에 포함되지 않습니다.

### CRC와 FEC

세그먼트 CRC는 [framing.py](../tngpkt/framing.py)의 바이트 단위 CRC-16/CCITT-FALSE 함수입니다. 다항식은 `0x1021`, 초기 레지스터는 `0xFFFF`이며, 입력·출력 비트 반전(reflection)과 최종 XOR은 없습니다. CRC는 상위 바이트부터 붙입니다.

FEC는 K=7, R1/2이며 생성다항식은 **0o133, 0o171 순서로 출력**합니다. 초기 여섯 비트 상태는 영입니다. 입력 비트 `u`와 상태 `s`에 대해 `reg=(u<<6)|s`로 놓고, 각 생성다항식에 대한 `reg & generator`의 패리티를 출력한 뒤 `s=reg>>1`로 갱신합니다. 마지막 여섯 개의 영 입력은 상태를 영으로 되돌립니다. [fec.py](../tngpkt/fec.py)와 `link7.conv_encode_rows`를 참고하십시오.

현재 활성 TNG44 경로에는 페이로드 화이트닝 단계나 전용 반복 메시지 결합기가 없습니다. CRC·패리티 계산의 XOR은 오류 제어 연산이며 암호화가 아닙니다.

### 인터리빙과 가드

부호 길이 `n`에 대해 `link7.interleaver_src`는 다음과 같이 정의합니다.

```python
p = arange(n)
tau = p + (p % 12) * 12 * 24
order = lexsort((p, tau))  # primary tau, secondary p
q = empty(n, integer)
q[order] = arange(n)
transmitted[q[p]] = coded[p]
```

수신은 `received[q]`를 읽어 부호 순서를 복원합니다. 무작위·비공개 인터리버 seed는 없으며, 등록된 범위는 약 3.2초입니다.

현재 스트리밍 가드는 공개 기본 가드의 홀수 인덱스 비트를 각각 반전한 것입니다. 이는 패킹된 각 바이트에 `0x55`를 XOR하는 것과 같습니다. 패킹된 바이트는 다음과 같습니다.

```text
0f 96 c3 3c 69 f0 87 7e 5a a5 66 99
```

이 가드 패턴 변환은 공개 프레이밍 식별 패턴을 선택하는 처리이며, 페이로드 화이트닝이나 비밀 매핑이 아닙니다.

### 동기와 수신기

기저대역 스트림에는 주파수 오프셋이 없는 300 ms 선행 톤, 시작 Costas 시퀀스 A, 두 가드를 포함한 모뎀 스트림, 끝 Costas 시퀀스 B가 들어갑니다.

```text
A = (3, 1, 4, 0, 6, 5, 2)
B = (0, 6, 4, 5, 1, 3, 2)
인덱스 k의 톤 오프셋 = (k - 3) * 62.5 Hz
심볼 길이 = 32 ms; 일곱 심볼 동기 각각 = 224 ms
```

동기는 연속 위상과 4 ms 주파수 전이 평활화를 사용합니다. [preamble.assemble](../tngpkt/preamble.py)은 동기 파형에 공개 200 Hz/129탭 LPF를 적용하고, 필터 꼬리를 인접 구간과 겹치며 데이터·동기 경계를 평활화합니다. 추가 정보 필드를 삽입하지는 않습니다.

수신기는 오디오를 하향 변환하고 시간·주파수 오프셋에 걸쳐 공개 동기 템플릿의 상관을 구합니다. 주파수를 보정한 뒤 주변 문맥을 포함한 모뎀 창을 평가해 프레임마다 96비트 LLR을 얻습니다. 디인터리빙, 연판정 비터비 복호, 각 세그먼트 CRC 검증을 수행합니다. 첫 유효 세그먼트는 페이로드 바이트 수를 제공합니다. 끝 동기는 수신 길이를 정하거나, 시작 동기를 놓쳤을 때 버퍼 오디오에서 복원을 시도하게 할 수도 있습니다. 정렬 가설과 재잠금(relocking)은 수신기 알고리즘이며 비밀 매핑이 아닙니다. CRC로 확인된 세그먼트에서만 부분 문자를 표시합니다. 주기적인 중간 동기 합류 표식은 없습니다.

등록된 29.5 문자/s는 반복적으로 발생하는 CRC/FEC 오버헤드를 포함한 긴 ASCII 메시지의 **증분** 전송률입니다. 고정된 선행 톤·동기·가드 오버헤드는 이 비교에서 상쇄됩니다. 예를 들어 ASCII 240자와 960자는 각각 데이터 프레임 44개와 171개가 필요합니다. 계산은 `720 / ((171-44)*0.192) = 29.5276`입니다. 이는 일반 UTF-8이나 전체 메시지 처리량을 보장하지 않습니다.

## TNG5: Robust

### 설계 목적과 절충

TNG5는 각 문자 단위에 더 많은 송신 시간을 사용해 약한 신호와 페이딩 조건을 목표로 합니다. 입력을 공개 57자와 EOT Huffman 코드북으로 제한하여 일반적인 지원 문자에 필요한 정보를 줄이고, K7 R1/4 FEC와 네 개의 완전한 부호어 사본으로 TNG44보다 훨씬 많은 중복 정보를 제공합니다. 더 긴 인터리버는 사본과 부호 관측을 시간상으로 분산하여 복호기가 페이딩 구간의 여러 부분에서 정보를 얻도록 합니다. 그 대가로 처리량이 낮아지고 충분한 관측을 기다리는 시간이 길어집니다.

각 세그먼트는 완전한 문자를 독립적으로 채웁니다. 따라서 누락된 세그먼트를 넘어 Huffman 복호 문맥을 이어갈 필요가 없으며, 뒤쪽 유효 세그먼트에서 부분 문자를 복원할 수 있습니다. 공개 고정 seed XOR 화이트닝은 오류 제어 부호화 전에 긴 동일 비트 패턴을 줄입니다. seed **4040**과 정확한 마스크는 아래에 정의합니다. 이 처리는 결정론적이고 되돌릴 수 있으며 비밀성 기능이 없습니다.

주기적인 중간 동기 표식은 긴 송신 중 수신기에 새로운 타이밍·주파수 기준을 제공하고, 시작을 놓친 뒤 합류를 시도할 수 있게 합니다. 합류에도 충분한 부호 관측과 CRC 확인이 필요하며, 수신기는 수집하지 못한 샘플을 재구성할 수 없습니다. TNG5는 별도의 공개 파형 모델 가중치를 사용하므로, 속도 조절로 TNG44를 느리게 한 모드가 아닙니다. 네 부호어 사본은 한 번의 송신에 속하며, TNG1처럼 나중에 다시 수신한 내용을 결합하는 방식과 다릅니다.

### 송신 정보 경로

```text
정규화한 문자 -> 공개 Huffman 부호
 -> 18바이트 세그먼트 (첫 세그먼트에 2바이트 세그먼트 수 포함)
 -> 원본 세그먼트의 CRC16
 -> 데이터 18바이트만 XOR 화이트닝
 -> 화이트닝 데이터 + 변경하지 않은 CRC -> 여섯 개의 영 테일 비트
 -> K7 R1/4 컨볼루션 부호 -> 네 개의 완전한 사본
 -> 공개 인터리버 -> 96비트 프레임 + 가드 -> 파형 모델
 -> 선행 톤/시작 동기, 주기적 중간 동기, 끝 동기 -> 오디오
```

첫 세그먼트에는 전체 세그먼트 수를 나타내는 두 빅엔디언 바이트와 **Huffman 문자 비트 128개**가 들어갑니다. 이후 세그먼트에는 **Huffman 문자 비트 144개**가 들어갑니다. 각 세그먼트는 CRC를 붙이기 전 정확히 18바이트입니다. 개수에는 첫 세그먼트도 포함되며, 바이트 수나 문자 수가 아닙니다. 공통 코드북, 공간이 있을 때의 EOT 삽입, 비트를 일로 채우는 패딩 규칙에 따라 세그먼트 경계마다 문자를 독립적으로 채웁니다.

### CRC와 공개 XOR 화이트닝

화이트닝 전 원본 18바이트 세그먼트는 TNG44와 같은 바이트 CRC-16/CCITT-FALSE로 보호합니다. 다항식은 `0x1021`, 초기값은 `0xFFFF`이며, 비트 반전과 최종 XOR은 없고 상위 바이트부터 전송합니다.

[tng5.py](../tngpkt/tng5.py)의 `WHITEN`, `whiten`, `seg_bits`는 다음과 같이 정의합니다.

```python
WHITEN = np.random.default_rng(4040).integers(
    0, 256, 18
).astype(np.uint8).tobytes()
whitened = bytes(x ^ y for x, y in zip(segment, WHITEN))
wire_information = whitened + crc16_ccitt(segment).to_bytes(2, "big")
```

현재 공개 마스크의 정확한 바이트 순서를 십육진수로 나타내면 다음과 같습니다.

```text
78 22 bf 5a 6f 0e 1e 81 18 f6 20 7e 46 1a 1e 56 1e 6f
```

이는 **고정 공개 seed 4040**을 사용하는 가역 XOR 화이트닝입니다. 마스크는 각 세그먼트마다 영 번째 바이트에서 다시 시작하며, 첫 세그먼트의 개수 필드와 패딩을 포함한 세그먼트 18바이트 전체에 적용합니다. CRC 바이트는 화이트닝하지 않습니다.

**목적은 비트 패턴 화이트닝이며 비밀성이 아닙니다. 비밀키를 사용하지 않습니다.** 코드에서는 긴 반복 비트 패턴을 이 단계의 이유로 명시합니다. 수신은 복원된 18바이트에 같은 XOR을 적용한 뒤, 그 결과인 **화이트닝을 되돌린 데이터**에 대해 CRC를 검증합니다. 이 연산에는 비밀번호, 협상된 키, 무작위 비공개 nonce, 실행 시 비밀 매핑이 들어가지 않습니다.

### FEC, 반복, 인터리버와 가드

각 세그먼트에는 정보 비트 160개(데이터 18바이트 + CRC 2바이트)가 들어갑니다. 여섯 개의 영 테일 비트를 추가한 뒤, 초기 상태 영에서 K=7, R1/4 생성다항식으로 부호화합니다.

```text
(0o117, 0o127, 0o155, 0o171)
```

`reg=(u<<6)|s`를 사용하여 해당 생성다항식 순서로 패리티를 출력하고 `s=reg>>1`로 갱신합니다. 이 과정에서 부호 비트 664개가 생성됩니다. **664비트 부호어 전체를 네 번 반복**하여 세그먼트마다 2656비트를 만듭니다(실효 R1/16). 디인터리빙 후 수신기는 정렬된 네 LLR 사본을 합산한 뒤 비터비 복호합니다. 이는 한 번의 송신 내부에서 이루어지는 FEC 반복이며, TNG1의 이후 송신 결합과 다릅니다.

전체 부호 길이 `n=2656*n_segments`에 대한 정확한 매핑은 다음과 같습니다.

```python
perm = np.random.default_rng(55).permutation(2656)
base = concatenate([perm + k*2656 for k in range(n_segments)])
p = arange(n)
tau = p + (p % 16) * 16 * 18  # floor(4800 / (16*16)) = 18
order = lexsort((p, tau))
q = empty(n, integer)
q[order] = arange(n)
mapping = q[base]
transmitted[mapping] = coded
```

수신기는 `received[mapping]`을 선택합니다. 공개 고정 seed는 **55**이고 기본 `ILV_SPAN`은 4800이며, 등록된 범위는 약 9.6초입니다. 이 순열은 오류를 분산하고 반복 사본을 분리하며 메시지를 은닉하지 않습니다.

마지막 96비트 프레임은 `default_rng(n).integers(0,2,count)`로 패딩합니다. seed는 공개 부호 길이 `n`입니다. 앞뒤에는 `default_rng(5005).integers(0,2,96)`로 생성한 공개 96비트 가드를 붙입니다.

```text
100110011111110000110011110110111101110011111011111101011100110000100101001010111011100100101010
```

패딩과 가드는 CRC가 붙은 사용자 정보가 아닙니다.

### 동기와 파형 성형

현재 송신 구조는 다음과 같습니다.

```text
300 ms 선행 톤 | 시작 A12 | 가드 | M_k를 포함한 데이터 프레임 | 가드 | 끝 B12
```

- 선행 톤 오프셋: `-2.5 * 125/3` Hz(약 −104.1667 Hz).
- 시작 A12: `(1,3,7,2,5,11,10,8,4,9,6,0)`, 톤당 64 ms, 간격 31.25 Hz, 총 768 ms.
- 끝 B12: `(9,8,6,0,5,1,11,3,4,7,2,10)`, 톤당 32 ms, 간격 31.25 Hz, 총 384 ms.
- 중간 동기 `M_k`는 **20*k < n_frames일 때만 데이터 프레임 20*k 앞에** 삽입합니다(프레임 인덱스는 영부터 시작하며 가드는 제외). 길이는 336 ms로, 48 ms 톤 일곱 개와 `125/3` Hz 간격을 사용합니다. 네 패턴은 `(k-1)%4` 순서로 순환합니다.

```text
M1: (1,4,3,5,2,0,6)
M2: (2,0,6,5,1,3,4)
M3: (2,1,6,4,0,3,5)
M4: (2,3,5,0,4,1,6)
```

동기 시퀀스 인덱스 `v`의 주파수 오프셋은 `(v-(max(sequence)+min(sequence))/2)*spacing`입니다. 동기 변조는 연속 위상과 **BT=0.5**인 가우시안 주파수 성형을 사용합니다. 데이터 대비 진폭 증가는 **+2.25 dB**이며 `10**(BOOST_DB/20)`으로 구현합니다. 동기 시퀀스는 한 번씩 전송하며, 이전 A×4/B×4 동기 반복은 현재 구조가 아닙니다.

[tng5.build_tx](../tngpkt/tng5.py)는 조립된 파형에 공개 200 Hz/129탭 LPF를 적용합니다. 중간 동기를 제외한 데이터·가드 포락선의 피크를 데이터 RMS +3 dB에서 클리핑하고 LPF를 적용하는 과정을 세 번 반복합니다. 이러한 파형 처리는 암호화된 필드를 추가하지 않습니다.

### 수신 복원과 합류

수신기는 시작·끝 동기와 중간 동기 패턴을 검출하고, 타이밍·주파수를 추정합니다. 삽입된 중간 동기 샘플을 건너뛰어 문맥 수신기에 데이터만 있는 창을 제공합니다. 공개 인터리버 순서를 복원하고 네 부호 사본을 합산한 뒤, 종단 연판정 비터비 복호를 수행합니다. 여섯 테일 비트를 제거하고 바이트로 다시 패킹한 뒤 **화이트닝을 되돌리고**, CRC를 검증하여 각 유효 세그먼트를 Huffman 복호합니다. 첫 세그먼트의 개수가 메시지 범위를 정하며, 실패 세그먼트에는 표시용 대체 기호를 사용합니다.

시작 확인에는 예상 위치의 첫 중간 동기 또는 유효한 세그먼트 CRC를 사용합니다. 현재 활성 `M_JOIN=True` 경로는 시작을 놓쳤을 때 중간 동기 가설도 검토하며, CRC로 합류를 확인합니다. 버퍼의 앞부분 누락 샘플은 소거(erasure)이며 비밀 데이터가 아닙니다. 합류는 부분 문자를 복원할 수 있지만 실패할 수도 있으며, 누락된 앞부분의 복원을 보장하지 않습니다. 수신기 재시도에서 LLR 관측을 결합할 수는 있으나, TNG5에는 TNG1 방식의 메시지 간 반복 결합 프로토콜이 정의되어 있지 않습니다.

## TNG1: Robust+

### 설계 목적과 절충

TNG1은 어려운 약신호·페이딩 채널에서 대화 속도보다 복원을 우선합니다. TNG5와 같은 57자와 EOT Huffman 경로를 사용하지만, 각 블록은 14.72초 동안 문자·제어·패딩 비트 64개만 전달합니다. 긴 160 ms 톤 심볼, K13 R1/4 테일바이팅 FEC, 블록 내부 인터리빙을 사용하며, 매우 낮은 문자 전송률을 감수하여 수신기에 더 긴 관측과 다른 오류 제어 구조를 제공합니다.

알려진 동기 톤을 모든 블록에 분산 배치합니다. 수신기는 여러 블록에서 포착 근거를 누적하고, 별도의 시작 프리앰블을 받지 않아도 합류를 시도할 수 있습니다. 이 동기 누적은 반복되는 알려진 배치를 이용하며, 연속 블록이 같은 문자를 담는다고 가정하지 않습니다. 각 블록의 CRC와 수신기 확인 검사가 복호된 내용을 수용할 수 있는지 결정합니다.

반복된 내용의 경우, 복호에 실패한 톤 에너지 관측을 보관하고 두 개 또는 세 개씩 결합할 수 있습니다. 약한 관측도 다른 사본에서 더 강하게 수신된 심볼에 유용한 근거를 보탤 수 있습니다. 결합에는 CRC 통과와 개별 관측의 일치 검사가 필요하므로, 에너지를 합산했다는 이유만으로 서로 무관하거나 사용할 수 없는 후보를 수용하지 않습니다. 다시 보내기는 이전 문자를 한 번 더 송신하며, 수신 확인 응답을 사용하는 자동 재전송 교환을 만들지는 않습니다.

현재 TNG1 경로는 처프가 있는 16-GFSK, 스펙트럼 에너지 측정, 명시적인 컨볼루션 복호를 사용합니다. **신경망이나 모델 체크포인트를 사용하지 않습니다.** 포착 지연, 부분 수신, 결합 범위는 수집된 오디오와 수신기 상태에 따라 달라집니다.

### 정보, CRC와 컨볼루션 톤 레이블

```text
정규화한 문자 -> 64비트 단위로 공개 Huffman 패킹
 -> 16비트 CRC 추가 -> 정보 비트 80개
 -> 테일바이팅 K13 R1/4 -> 0..15 레이블 80개
 -> 공개 80심볼 인터리버
 -> 공개 동기 톤 12개 삽입 -> 톤 심볼 92개
 -> 처프가 있는 16-GFSK -> 오디오; 필요에 따라 블록 반복
```

각 블록은 문자·제어·패딩 비트 64개와 CRC 비트 16개를 전달합니다. 공통 Huffman 부호는 블록 경계를 넘지 않게 채웁니다. 송신기는 EOT가 실제로 삽입될 때까지 계속하며, EOT만 들어 있는 블록을 추가할 수도 있습니다. 블록에는 순번 필드, 비밀 주소 필드, 재전송 표식이 없습니다.

[tng1.crc16_bits](../tngpkt/tng1.py)는 패킹된 문자 비트 64개 전체를 최상위 비트부터 처리하며, 다항식은 **0x1021**입니다. 일반적인 초기 레지스터는 **0xFFFF**입니다. 메시지 첫 블록은 **0x5A5A**를 사용합니다. 이는 현재 wire revision 2에서 도입한 공개 첫 블록 표시입니다. 각 입력 비트와 레지스터 최상위 비트를 XOR하고, 레지스터를 왼쪽으로 시프트한 뒤, XOR 결과가 일이면 다항식을 XOR합니다. 비트 반전과 최종 XOR은 없습니다. 결과 레지스터의 16비트를 최상위 비트부터 붙입니다. 수신기는 해당 CRC 초기값을 확인하여 첫 블록을 구분합니다. 이 초기값은 키가 아닙니다.

테일바이팅 컨볼루션 부호기는 **K=13**, 상태 수 4096이며, 생성다항식은 정확히 다음 순서입니다.

```text
(0o13635, 0o12055, 0o15727, 0o17453)
```

TNG44/TNG5와 달리 영 종단 테일을 붙이지 않습니다. 정보와 CRC를 합친 80비트 시퀀스의 마지막 12비트를 상태 갱신에 입력하여 초기 상태를 정합니다. 각 비트 `u`에 대해 다음을 수행합니다.

```text
reg = (u << 12) | state
label = concatenate parity(reg & g) for the four generators, MSB first
state = reg >> 1
```

레이블은 **0..15**의 정수이며 톤을 직접 선택합니다. 추가 Gray 매핑이나 비공개 치환표는 없습니다. 최종 상태는 테일바이팅 초기 상태와 같습니다.

### 고정 블록 배치와 인터리버

각 블록은 **데이터 심볼 80개 + 동기 심볼 12개**로 구성하며 **심볼당 160 ms**, 총 **92*0.160 = 14.72초**입니다. 모든 블록은 같은 배치를 사용합니다.

[tng1.layout](../tngpkt/tng1.py)은 공개 NumPy `default_rng(11)`을 사용합니다. 동기 위치 지터용 균등분포 값 12개를 뽑고, 다음으로 톤 순열 16개, 데이터 심볼 순열 80개를 만듭니다. 실행 시 엔트로피나 비밀 seed를 제공하지 않습니다. 이 설정의 정확한 배열은 다음과 같습니다.

```text
sync positions = [3,11,19,26,34,43,49,57,66,73,80,88]
sync tones     = [4,15,0,13,6,9,11,10,2,1,12,8]
```

나머지 블록 위치를 위치 오름차순으로 `encoded_labels[ilv]`로 채웁니다. 해당 순열은 다음과 같습니다.

```text
ilv = [16,36,62,78,33,24,18,39,6,32,20,59,53,47,70,55,48,64,56,76,65,41,77,15,40,71,63,52,9,37,38,30,13,68,21,43,60,3,11,74,26,35,4,34,29,7,75,73,25,2,67,28,5,44,31,1,79,49,58,72,54,45,23,17,69,14,46,57,61,19,8,51,22,10,50,66,12,0,27,42]
```

수신 복원에는 `original_metrics[ilv] = transmitted_data_metrics`를 사용합니다. 이는 블록 내부 순열이며, 14.72초의 추가 지연이나 암호학적 셔플이 아닙니다.

현재 활성 TNG1에는 **바이트 화이트닝·스크램블링 단계가 없습니다**. CRC/FEC XOR 연산과 결정론적 배치는 공개 오류 제어·매핑 처리입니다.

### 실제 변조 매핑

TNG1은 신경망 모델 대신 **심볼마다 상향 처프가 있는 16-GFSK**를 사용합니다. 톤 레이블 `m`, 심볼 길이 `T=0.160`초에 대해 다음과 같습니다.

```text
slot[m] = m - 7.5
공칭 톤 주파수 오프셋 = slot[m] / T = (m-7.5)*6.25 Hz
```

초당 1000개 기저대역 샘플에서 각 공칭 톤 주파수를 160샘플 동안 반복하고, 톤 주파수 스트림을 **BT=2**로 가우시안 평활화합니다. 공개 처프 샘플은 다음과 같습니다.

```text
chirp[n] = 50 * ((n+0.5)/160 - 0.5) Hz, n=0..159
```

처프는 심볼마다 추가하며, 되돌아오는 부분은 **BT=8**로 별도 평활화합니다(`chirp_smooth=False`, `chirp_bt=8`). 합한 주파수를 적분해 `phase=2*pi*cumsum(f)/1000`으로 위상을 만들고 `exp(j*phase)`를 출력합니다. [tng1.gfsk](../tngpkt/tng1.py)에 가우시안 커널 절단과 끝점 확장을 정확히 정의합니다. 스트림 시작·끝에는 20 ms 램프를 적용한 뒤 리샘플링하고 선택한 오디오 중심 주파수로 옮깁니다.

별도 시작 프리앰블, 끝 Costas 시퀀스, TNG5 방식의 중간 동기는 없습니다. **모든 블록**에 분산된 열두 동기 톤으로 지정된 시간 슬롯 없이 블록 포착과 합류를 지원합니다.

### 수신 복원과 반복 결합

오디오를 초당 1000샘플의 복소 기저대역으로 하향 변환합니다. 수신기는 임펄스 블랭킹을 적용하고 처프를 제거한 스펙트럼 에너지를 계산합니다. 알려진 동기 위치를 최대 네 블록에 걸쳐 접어 누적하여 타이밍·주파수 후보를 찾습니다. 심볼 창의 처프를 제거하고 알려진 소수 톤 오프셋만큼 이동시킨 뒤, 공개된 16개 톤 빈에서 FFT 에너지를 읽습니다.

데이터 심볼 메트릭을 디인터리빙하고 테일바이팅 연판정 비터비로 복호합니다. 수신기는 일반·첫 블록 CRC 규칙을 검증한 뒤 정보 비트 64개를 Huffman 복호합니다. 최초 CRC가 실패하면 설정된 다중 심볼 재시도에서 양쪽으로 두 심볼씩 이웃 구간을 사용합니다(`msd=2`). 수용되는 블록은 수신기 동기·확인 규칙도 만족해야 합니다. EOT는 메시지를 끝내며, 신호 소실 처리로 불완전한 메시지를 끝낼 수도 있습니다. 수신기는 뒤쪽 블록에 합류하여 앞부분 누락 표시를 나타낼 수 있습니다.

**다시 보내기(Resend)**는 마지막 TNG1 문자를 새 블록 경계에서 다시 송신합니다. 무선 전송 재시도 번호나 숨겨진 반복 메시지 식별자는 없습니다. `Tng1Stream`은 실패 후보 에너지를 저장하며, `Combiner`는 심볼 메트릭을 합산하여 두 개와 세 개의 결합을 시도합니다. 유효한 CRC와 재부호화한 후보에 대한 사본별 일치가 필요합니다. 현재 `Tng1Stream`은 `zmin=5`를 사용하고, 순위를 매긴 후보를 최대 16개 보관하며 600초가 지나면 만료시킵니다. 사본 유사도에 따라 시도할 조합을 제한합니다. 이는 같은 반복 내용의 복원을 개선할 수 있으나 보장되는 것은 아니며 암호화가 아닙니다.

## TNG44/TNG5 파형 매핑과 공개 모델

실제 데이터 변조는 고정된 네 점 성상도 표가 아니라 공개 코드 **및 함께 제공되는 수치 가중치**로 정의합니다. 매핑은 위치에 따라 달라집니다. 코드와 가중치가 이 매핑을 공개적으로 정의합니다.

| 모드 | 공개 체크포인트 | SHA-256 |
|---|---|---|
| TNG44 | [stage3.pt](../models/stage3.pt) | `e73e59a5e2d7dade6907140a6243eb87793b48dcea6570be543a5cf32533d30c` |
| TNG5 | [stage3_strong.pt](../models/stage3_strong.pt) | `2cbd875d00c3408459d147a6dac28d8a09713c0592b2253b81e1115e59981c4c` |

제공되는 두 체크포인트 설정은 모두 기저대역 2000 Hz, 변조 심볼당 8샘플, 심볼당 부호 비트 2개, 프레임당 48심볼입니다. 따라서 부호 비트 96개는 384샘플(192 ms)로 매핑됩니다. 위치 임베딩은 16개 값이고 송신기 은닉층 폭은 (256,256)입니다. 200 Hz/129탭 고정 FIR과 양쪽 각각 네 심볼의 수신 문맥을 사용합니다(수신 창 448샘플).

[models3.StreamTransmitter](../tngpkt/models3.py)는 다음과 같이 매핑을 정의합니다.

1. 부호 스트림 비트를 순서가 있는 쌍으로 묶습니다. 묶기 전에 적절한 공개 96비트 가드를 앞뒤에 붙입니다.
2. 변조 심볼 인덱스 `j`에 대해 위치 임베딩 `pos[j % 48]`을 사용하고 `2*bits-1`과 이어 붙입니다.
3. 체크포인트의 MLP를 Linear, GELU, Linear, GELU, Linear 순서로 적용하여 복소 샘플 여덟 개에 해당하는 실수 출력 16개를 얻습니다. 인접한 실수 출력 쌍을 I와 Q로 재구성합니다.
4. 이 샘플을 스트림으로 이어 붙이고 체크포인트의 공개 고정 FIR을 **전체 스트림에 한 번** 적용한 뒤, 평균 복소 전력으로 정규화합니다.
5. [modem5._frames_to_baseband](../tngpkt/modem5.py)는 20 ms 경계 램프를 적용하고 다시 정규화합니다. 이후 각 모드는 앞에서 설명한 동기와 파형 성형을 추가합니다.

FIR 계수와 정규화는 [waveform.design_lpf](../tngpkt/waveform.py)에서 공개적으로 생성하며, 해당 버퍼도 체크포인트에 들어 있습니다. 실행 시 로딩은 송수신기 파라미터를 함께 제공되는 상태 딕셔너리로 대체합니다. 실행 시 생성한 비밀 매핑을 선택하지 않습니다.

[models3.ContextReceiver](../tngpkt/models3.py)는 공개 FIR과 RMS 정규화, 두 채널 I/Q 컨볼루션 층, 심볼 다운샘플링, 잔차 블록, 전역 문맥, 두 비트 로짓 출력 헤드를 사용합니다. 수치 가중치는 연판정 비트 복조를 정의합니다. [modem4._rx_windows](../tngpkt/modem4.py)는 이 로짓을 부호 비트 순서로 평탄화합니다. 양수 LLR은 비트 1을 지지합니다. 이후 FEC/CRC가 공개 문자 부호화를 복원하고 검증합니다.

전체 텐서 값은 연결된 공개 체크포인트에 있으며, 이 문서에 수천 개의 인위적인 성상도 항목으로 옮겨 적지 않습니다. TNG44/TNG5의 호환 가능한 교신에는 일치하는 wire revision과 모델 식별자가 필요합니다. TNG1에는 체크포인트가 필요하지 않습니다.

## 설계와 개발 방법의 근거

공개 소스에는 부호화, 동기, 파형 복원을 소프트웨어로 검증하는 경로가 있습니다. [modem5.cmd_loopback](../tngpkt/modem5.py)은 파형을 생성해 오디오로 변환하고, 주파수 오프셋, 선택적 사운드카드 클록 불일치, 대역 제한 가우시안 잡음을 적용합니다. 결과를 복호한 뒤 복원한 문자와 입력을 비교합니다. [modem.add_band_noise](../tngpkt/modem.py)는 해당 경로의 잡음 추가를 정의합니다.

[tng1.channel](../tngpkt/tng1.py)은 AWGN과 두 경로 Watterson 방식의 페이딩 시뮬레이션을 제공합니다. 가우시안 도플러 이득, 지연, 주파수 오프셋·드리프트, 레벨 변화, 선택적 임펄스 잡음을 포함합니다. 이 함수들은 공개 구현에서 어떤 손상을 모사할 수 있는지 보여줍니다. 검증용 보조 함수이며 추가 전송 필드나 실제 무선 채널 자체가 아닙니다.

소스 주석에는 동기, 클리핑, 문자 패킹의 파라미터 비교가 설명되어 있으나, 참조한 실험 스크립트와 결과 로그 중 상당수는 이 공개 트리에 없습니다. 해당 주석만으로 재현 가능한 성공률, 채널 한계, RF 검증 완료를 입증할 수는 없습니다. 이 문서에서는 확인하지 못한 개발 기록이나 이전 설정으로 현재 프로토콜을 정의하지 않습니다.

## 공개 변환과 비밀성 점검

현재 활성 부호화·복원 경로는 아래의 공개 변환을 사용합니다. 비밀키 메시지 암호화, 비공개 문자 매핑, 메시지 은닉 기능을 제공하지 않습니다. 문자표, 전체 Huffman 코드북, 프레이밍, CRC/FEC, 인터리버, 화이트닝 seed·알고리즘, 변조 매핑은 이 문서와 연결된 소스에 공개되어 있습니다. 누구나 이 정의를 검토하여 무선 전송 데이터 구조를 분석할 수 있습니다. 이러한 공개성이 손상된 오디오의 성공적인 복호를 보장하지는 않습니다.

| 현재 활성 공개 연산 | 위치 | Seed / 초기값 | 통신 목적 |
|---|---|---|---|
| TNG5 가역 데이터 XOR 화이트닝 | `tng5.WHITEN / whiten / seg_bits / decode_llr`; `tng5_app.decode_one` | 고정 공개 seed **4040**, 위의 정확한 18바이트 마스크 | 긴 반복 비트 패턴 감소; CRC 검증 전에 되돌릴 수 있음 |
| TNG44 현재 가드 반전 | `link7.GUARD_V2` | 고정 교대 비트 마스크(패킹 시 `0x55`) | 현재 스트리밍 프레이밍 식별 패턴 확인 |
| TNG44 지연 인터리버 | `link7.interleaver_src` | RNG 없음; J=12, M=24 | 부호 비트를 시간상으로 분산 |
| TNG44 마지막 부호 프레임 채움 | `link7.encode_raw`, `stream_ui.encode_bytes` | 공개 **0xF111** | 사용하지 않는 비정보 프레임 비트 채움 |
| TNG5 세그먼트 내부 순열 | `tng5._PERM / interleave_map` | 공개 **55** | 부호 사본 분리·분산 |
| TNG5 가드 | `tng5.GUARD5` | 공개 **5005** | 고정 모뎀 가드 파형 |
| TNG5 마지막 부호 프레임 채움 | `tng5.encode_bits`, `tng5_app.frames_from_segs` | 공개 부호 길이 **n** | 사용하지 않는 비정보 프레임 비트 채움 |
| TNG1 동기와 심볼 인터리버 | `tng1.layout` | 공개 **11**, 위의 배열 | 알려진 포착 톤과 오류 분산 |
| CRC/FEC 패리티 XOR | `framing`, `fec`, `link7`, `tng1`, `conv_sim` | 위의 공개 다항식·상태 규칙 | 오류 검출·정정 |
| 모델과 문자 집합 SHA-256 | `registry` | 공개 파일·표 내용 | 호환성 식별; 페이로드 암호화가 아님 |

그 밖의 활성 페이로드 화이트닝·스크램블러는 확인되지 않았습니다. 이전 파일 복호기와 내부 진단·예제용 잡음 생성은 현재 송신 형식이 아닙니다. 정렬·캐시·UI에서 사용하는 `key`라는 이름은 암호학적 키가 아닙니다. UI 컬러맵 조회표는 문자 매핑이 아닙니다. 모델 학습 seed 메타데이터는 실행 시 비밀 무선 전송 매핑을 생성하는 데 사용되지 않습니다.

이 문서는 통신 동작을 설명하며, 특정 관할권의 아마추어무선 규정이 법적으로 적용되는지를 설명하지 않습니다. CRC가 송신자를 인증한다거나, FEC가 기밀성을 제공한다거나, 모든 채널을 복호할 수 있다고 주장하지 않습니다.

## 구현 참조와 제한

위의 문자표, 바이트·비트 배치, CRC/FEC 규칙, 순열, 화이트닝 마스크, 동기 시퀀스, 변조 규칙은 현재 활성 무선 전송의 주요 구조를 다룹니다. 정확한 DSP 커널 구성, 리샘플링, 부동소수점 가중치, 수신기 후보 문턱값은 연결된 공개 소스와 체크포인트 파일에 정의되어 있습니다. 비공개 외부 표는 필요하지 않습니다.

현재 실시간 송신은 문서 앞의 표에 있는 revision만 사용합니다. TNG5 wire revision 1에는 파일 전용 복호기가 있습니다. 현재 구현은 revision 2와 3을 문자로 복호하지 않습니다. TNG1 wire revision 1은 파일 전용 대체 경로로 지원합니다. 이전 WAV 대체 경로가 이전 revision과의 실시간 상호운용성을 뜻하지는 않습니다. 수신기의 포착, 결합, 합류는 조건부 알고리즘이며, 이 설명은 모든 잡음·페이딩 조건에서 수신 성공을 약속하지 않습니다.
